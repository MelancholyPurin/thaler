# Code architecture

- `internal/core` is the only code that touches the database. The TUI and the CLI depend on the `core.Service` interface and nothing else, so a server client can replace the local SQLite backend later. File-level operations that must work when the database does not open (restore, decrypt, prune) live in `core` but work on files, outside `Service`.
- Money is `ledger.Money`, whole minor units in an `int64`; never floats. Transactions are postings that sum to zero.
- `config.toml` rejects unknown keys. Defaults live in `internal/config` next to the key (`DefaultBackupReminderDays`), as a pointer when "unset" must differ from `0`.
- The backup folders are defined once, in `internal/config` (`BackupDir`, `ReplacedDir`, `PreMigrationDir`), and the one listing of backups is `core.ListBackups`. Do not rebuild those paths or globs elsewhere.
- **TUI:** one `mode` per popup, its state in a pointer on `Model`, keys in `updateX`, drawing in `xPopup`. Work that can take a moment (backups, restores) runs through `m.start(note, cmd)` so the screen keeps drawing; the popup ignores keys meanwhile, and `ctrl+c` waits. Tests finish that work with `settle(m)`. A new key goes in the `?` help list, the README key table and, if it matters, the bottom-bar hints.
- A story that is merged unfinished goes behind a feature flag (`Config.Enabled`, with the flag listed in `knownFeatures` in `internal/config/features.go`): off unless `config.toml` has it under `[features]`. Finishing the story deletes the flag and the checks, and the release notes say so. Nothing is behind a flag yet.
- **Errors a person sees** are `coded.New("some_code", args)` (package `internal/coded`), not a text: the code is stable (clients, tests and the API rely on it) and names a message in the catalog, with the same rules as any message. The ledger and the service make them without knowing any language; the TUI shows them with `m.errText(err)`, the CLI with `a.errorLine(err)`, both `Localizer.Error`, which also finds a coded error inside a wrapper (`fmt.Errorf("x: %w", err)`). Never flatten one with `%v`, which loses the code. A sentinel is `coded.New("code", nil)`, and `errors.Is` matches by code. Tests in `core` and `ledger` compare the code (`account_not_found(Name=X)`) or the English text through `errText`. Most errors are still plain English text and move over with `TLC-1` and `CLI-15`; new ones a person can see are coded from the start.
- **Counts** ("1 backup", "2 backups") are one message with a text per plural form, `{"one": "{{.Count}} backup", "other": "{{.Count}} backups"}`, and `loc.T(id, map[string]any{"Count": n})` chooses the form the way the language counts; never `(s)` or a hand-made plural. Only `Count` chooses the form, so phrase a message with a second number ("keep 3, remove 1 backup") so that the other number needs no agreement ("Kept per folder: 3. 1 backup would go"). `make i18n-check` requires a translation to have the `one` text wherever English has it. The older `(s)` texts move over with `TLC-1` and `CLI-15`.
- **Messages:** text for the person goes through `internal/i18n`: `loc.T("some_id", args)`, with the message in `internal/i18n/locales/en.json` (the source of truth: lower-case underscore ids that do not change once used, `{{.Name}}` arguments) and its translations in `es.json` and `de.json`; a missing translation shows English. In the TUI, write money and dates through `m.loc` (`Money`, `Amount`, `Signed`, `Date`, `StoredDate`; typed dates through `ParseDate`), never `Money.String()` or `ledger.DateLayout`, which are the plain form for `thaler cli` and for storage. Pass what you wrote into a message as an argument. Keep messages whole sentences, never built by concatenation. Most existing text is still inline English and moves over in `TLC-1` and `CLI-15`; new text goes in the catalog from the start. The names Thaler gives accounts (the five types, `Expenses:Uncategorized`, `Income:Uncategorized`, `Equity:Transfers`, `Equity:Conversions`, `Equity:Opening`) are stored in English, in `ledger`, and never change with the language. Something a person only reads is shown with `m.loc.AccountName(name)` (the type translated, `Activos:Bank`) or `m.loc.ShortName(name)` (without the type, as the lists do); something they type, a rule's category or a name sent to the service is the stored name. Tests never read the machine's language: the app takes `getenv`, and tests give it none. `make i18n-todo LOCALE=es` lists what a language lacks. `make i18n-check` (in `make test` and CI) fails on a message that is unused, unknown, stale or has changed arguments, and on a message missing from a language marked `Complete` in `internal/i18n/i18n.go`: clear that flag when a story adds messages before the translators have them, and set it when the language is whole again. The id given to `T` must be a string literal so that it can be checked. `language = "pseudo"` is the pseudo-language (accented, 40% longer, in brackets) for finding text that does not fit.
