# thaler

[English](README.md) · Español · [Deutsch](README.de.md)

Un planificador de finanzas personales que funciona en local. Un único binario de Go, un único archivo SQLite, sin servidor y sin sincronización con el banco.

- Contabilidad por partida doble (cuentas, transacciones, asientos), con los importes guardados como números enteros de la unidad mínima de cada moneda
- Varias monedas: la moneda base es EUR por defecto y puede cambiarse a USD, MXN o cualquier otro código
- Importación idempotente de extractos del banco, con categorización por reglas: CSV (incluido para la **Hamburger Sparkasse**, con perfiles propios para otros bancos), OFX y QIF
- `thaler` abre la interfaz interactiva del terminal (paneles al estilo de lazygit); cada operación existe también como subcomando `thaler cli …`, así que se puede automatizar (cron, shell)

> **Estado: temprano, para una sola persona.** Funciona en local y tiene pruebas, y el perfil de importación de la Sparkasse se ha probado
> con un extracto real, pero no hay modo multiusuario ni servidor (véase la [hoja de ruta](#hoja-de-ruta)).

## Instalación

Thaler funciona en un terminal en **macOS y Linux**, Intel y ARM. Es un solo archivo y no necesita compilador de C ni otras bibliotecas. Windows no está soportado; la aplicación web prevista para más adelante funcionará en cualquier navegador. Puedes descargar una versión publicada o compilarlo desde el código fuente, para lo que hace falta **Go 1.27 o posterior**. Hay un paquete de Homebrew previsto (`PLT-7` en la [hoja de ruta](ROADMAP.md)).

**Una versión publicada.** Cada versión de la [página de versiones](https://github.com/melancholypurin/thaler/releases) tiene un archivo comprimido por sistema (`thaler_<versión>_darwin_arm64.tar.gz` para un Mac con chip de Apple, `darwin_amd64` para un Mac con Intel, `linux_amd64` y `linux_arm64`) y `checksums.txt` con su firma, `checksums.txt.sigstore.json`. Comprueba que las sumas de verificación las firmó el flujo de publicación de este repositorio, comprueba con ellas el archivo que descargaste, descomprímelo y pon `thaler` en tu `PATH`:

```sh
cosign verify-blob --bundle checksums.txt.sigstore.json \
  --certificate-identity-regexp '^https://github\.com/MelancholyPurin/thaler/\.github/workflows/release\.yml@refs/heads/(main|release/[0-9]+\.[0-9]+)$' \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com checksums.txt
grep thaler_0.3.0_linux_amd64.tar.gz checksums.txt | sha256sum -c      # en macOS: shasum -a 256 -c
tar -xzf thaler_0.3.0_linux_amd64.tar.gz
mkdir -p ~/.local/bin && mv thaler ~/.local/bin/                        # ~/.local/bin tiene que estar en el PATH
thaler --version
```

El primer comando necesita [cosign](https://docs.sigstore.dev/cosign/system_config/installation/) (`brew install cosign`). Muestra `Verified OK` cuando las sumas las firmó el flujo Release de `MelancholyPurin/thaler`, ejecutado desde `main` o desde una rama de versión: la firma no usa clave, se hace a través de [Sigstore](https://www.sigstore.dev) con la identidad que GitHub da a ese flujo y queda en el registro público de Sigstore, así que no hay ninguna clave en la que confiar ni que perder. Las versiones se firman desde `v0.3.0`; `v0.1.0` y `v0.2.0` solo tienen las sumas. Los binarios en sí no están firmados ni notarizados por Apple. Si descargas uno con el navegador en un Mac, macOS se niega a abrirlo la primera vez; `xattr -d com.apple.quarantine thaler` lo resuelve (una descarga con `curl` no queda marcada).

**Desde el código fuente.** Los mismos pasos para Go y para Thaler, en dos partes:

**1. Consigue Go.** En macOS, `brew install go`. En Linux, sigue [go.dev/doc/install](https://go.dev/doc/install): el paquete de la propia distribución suele ser anterior a 1.27. `go version` dice cuál tienes.

**2. Instala Thaler.** Directamente desde GitHub:

```sh
go install github.com/melancholypurin/thaler/cmd/thaler@latest
```

o desde un clon, que deja `./thaler` y le da su versión a partir de git:

```sh
git clone https://github.com/melancholypurin/thaler
cd thaler
make build
```

`go install` pone `thaler` en `$(go env GOPATH)/bin` (`~/go/bin` si no lo cambiaste). Si después la shell dice `thaler: command not found`, añade esa carpeta al `PATH` en `~/.zshrc` (macOS) o `~/.bashrc` (Linux) y abre un terminal nuevo:

```sh
export PATH="$PATH:$(go env GOPATH)/bin"
```

**3. Compruébalo.** `thaler --version` muestra la versión y `thaler` abre la interfaz. La base de datos y la configuración están en las mismas carpetas en ambos sistemas (véase más abajo).

## Primeros pasos

```sh
thaler cli account add Assets:Sparkasse --currency EUR
thaler cli import --account Assets:Sparkasse --dry-run export.csv   # vista previa, no escribe nada
thaler cli import --account Assets:Sparkasse export.csv
thaler cli balance
thaler cli budget set Expenses:Groceries 400   # un objetivo mensual
thaler cli budget                              # este mes frente a sus objetivos
thaler cli list -a Expenses:Uncategorized

thaler                         # sin argumentos: la interfaz interactiva
thaler --version               # qué compilación es esta
```

`thaler --version` muestra la versión con la que se compiló el binario. `make build` la toma de git (la etiqueta más cercana, si no el commit, con `-dirty` cuando hay archivos cambiados); un `go build` o `go install` normal usa la versión que registró Go, y `dev` cuando no registró ninguna. Desde un clon, ejecuta los comandos como `./thaler`.

Exporta tus transacciones desde la banca en línea de la Sparkasse como CSV, eligiendo el formato **CSV-CAMT** (la variante CSV-MT940 usa los mismos nombres de columna que lee thaler).

**OFX y QIF.** Un banco que ofrece un extracto OFX (también llamado QFX, por Quicken) o un archivo QIF no necesita perfil: los perfiles incluidos `ofx` y `qif` los leen, y `auto` los reconoce por sus primeras líneas. De un extracto OFX, cada transacción es una fila con su día de contabilización, su importe en la moneda que indica el extracto, el nombre de la otra parte, la nota y el tipo de transacción (`POS`, `DEBIT`, que las reglas ven como un texto de contabilización); las versiones 1 y 2 funcionan, y un archivo con los extractos de varias cuentas se rechaza, porque una importación va a una sola cuenta. Un archivo QIF de una cuenta bancaria, de efectivo o de tarjeta de crédito da la fecha, el importe, el destinatario, la nota y el número (`N`), en la moneda de la cuenta; la categoría que pueda indicar se deja a tus reglas, y un archivo de una cuenta de inversión se rechaza. Una fecha QIF no tiene un orden fijo, así que se usa el primer orden que lee *todas* las fechas del archivo, los europeos antes que el estadounidense de Quicken, `10/4'26`: un archivo cuyos días son todos 12 o menos podría ser cualquiera de los dos, así que si tu banco escribe `DD/MM/YY`, añade un perfil con `format = "qif"` y sus `date_formats` (véase `config.example.toml`), que `auto` preferirá entonces.

**Cómo se lee un archivo.** El carácter entre columnas y la codificación se averiguan a partir del archivo, no se suponen. El delimitador es el de `;`, `,`, tabulador y `|` que divide la cabecera en las columnas que necesita el perfil (si ninguno lo hace, el que más la divide, para que el error muestre la cabecera de forma legible). La codificación es UTF-8, UTF-16 (con marca de orden de bytes, o reconocida por sus bytes cero; lo que una hoja de cálculo guarda como "texto Unicode") o, para todo lo demás, Windows-1252, que los bancos alemanes todavía usan. Así, un extracto que una hoja de cálculo abrió y volvió a guardar con comas, o como UTF-16 con tabuladores, se sigue importando con el perfil `sparkasse` y `auto` lo sigue reconociendo. `thaler cli import --dry-run` dice cómo se leyó el archivo. Un perfil tuyo puede fijar cualquiera de los dos: `delimiter = ";"`, `encoding = "utf-8"` (o `"utf-16"`, `"utf-16le"`, `"utf-16be"`, `"windows-1252"`); ambos valen `"auto"` por defecto.

Los datos están en `~/.local/share/thaler/thaler.db`, legibles solo por ti esté donde esté (Thaler hace privado el archivo al abrirlo), y la configuración en `~/.config/thaler/config.toml`. Se cambian con `--db` / `--config`, o con `THALER_DB`, `XDG_DATA_HOME`, `XDG_CONFIG_HOME`.

## Categorizar: `config.toml`

Cada clave, con lo que admite y su valor por defecto, está en [docs/config.es.md](docs/config.es.md).

En la interfaz, pulsa `C` en cualquier pantalla para abrir la configuración en tu editor (`$VISUAL`, si no `$EDITOR`, si no `nano` o `vi`; con un editor gráfico usa su opción de espera, p. ej. `EDITOR="code --wait"`). Si todavía no hay archivo, se crea a partir de `config.example.toml` con todos los ejemplos desactivados. Al cerrarse el editor, Thaler vuelve a leer el archivo y te dice si tiene algún error. Sin la interfaz, copia tú `config.example.toml` a `~/.config/thaler/config.toml`. Añade reglas así:

```toml
[[rule]]
contains = "REWE"
category = "Expenses:Groceries"
```

Gana la primera regla que coincide. Lo que no coincide con ninguna va a `Expenses:Uncategorized` / `Income:Uncategorized`. Las reglas se aplican al importar y otra vez cuando lo pidas: después de editar tus reglas, `thaler cli recategorize --dry-run` muestra una vista previa y `thaler cli recategorize` las aplica a todo lo que sigue sin categoría. Las transacciones que categorizaste tú nunca se tocan.

**Idioma.** Thaler habla inglés, español (`es`) y alemán (`de`). `language = "de"` en `config.toml` lo elige (en la interfaz, `ctrl+l` abre una lista de los idiomas: la pantalla cambia al instante, sin reiniciar, y Thaler escribe `language = "…"` en `config.toml` por ti, cambiando solo esa línea y dejando tus comentarios y reglas como están; si el archivo no se puede escribir, el idioma cambia igualmente hasta que salgas, y la línea de estado lo dice); sin esa clave decide el entorno (`LC_ALL`, `LC_MESSAGES` y luego `LANG`, como en `de_DE.UTF-8`), y un idioma que Thaler no habla es inglés. En la interfaz, los importes y las fechas se escriben como los escribe el idioma: `1,234.56` en inglés, `1.234,56` en alemán y en español, y las fechas como `2026-10-01` en inglés (ISO, que no puede leerse como mes primero ni día primero), `01.10.2026` en alemán y `01/10/2026` en español. Una fecha que escribes se lee en ese formato además de en ISO y `DD.MM.YYYY`, así que `01/10/2026` se entiende en español y se rechaza en inglés por ambigua; un importe se lee como antes, de cualquiera de las dos formas (`12.50` o `12,50`), y un valor como `1,234` se rechaza por ambiguo. `thaler cli` está en inglés sea cual sea el idioma elegido, y muestra importes y fechas en la forma simple (`1234.56`, `2026-10-01`), para que los scripts no cambien con el idioma del equipo; lee `YYYY-MM-DD` y `DD.MM.YYYY` y rechaza una fecha con barras por ambigua. Cada pantalla y ventana cabe en un terminal de 80 columnas por 24 filas en los tres idiomas, y una prueba dibuja unas setenta en cada idioma para demostrarlo: un texto largo pasa a la línea siguiente, la barra inferior omite las indicaciones de teclas menos útiles cuando la línea está llena (`?` siempre las lista todas), un estado largo pierde sus últimas partes, y la ayuda de `?` se desplaza con `↑`/`↓` cuando es más alta que la pantalla. Los recuentos también siguen el idioma (`1 copia de seguridad`, `2 copias de seguridad`). Los nombres que Thaler da a las cuentas se escriben en el idioma en que los lees en la interfaz: los tipos (`Assets:Bank` es `Activos:Bank` en español y `Vermögen:Bank` en alemán) y las cuentas que crea (`Expenses:Uncategorized` es `Gastos:Sin categoría`); los nombres que elegiste tú se quedan como están. Se guardan en inglés, y eso es lo que escribes, lo que muestra `thaler cli` y lo que nombra una regla en `config.toml`, así que nada cambia en tus datos ni en tus scripts cuando cambia el idioma. Los errores se buscan en el mismo catálogo, por el código estable que les da el servicio (`account_not_found`, `transfer_same_account`, …), así que siguen el idioma en la interfaz (la línea de comandos los muestra en inglés), vengan del libro contable, del servicio, del importador o del archivo de configuración (un error que envuelve a otro, como un archivo que no se puede leer, se traduce y después muestra las palabras del propio sistema). Todo lo que muestra `thaler cli` (ayuda, opciones, mensajes, errores) está solo en inglés, a propósito. Todo el texto de la interfaz (cada etiqueta, indicación, ventana, línea de estado y la ayuda de `?`) está en el catálogo de mensajes y traducido al español y al alemán; un mensaje que le falte a un idioma se muestra en inglés. El español se ha revisado y comprobado por completo; el alemán también se ha revisado y es lo bastante bueno para usarlo, pero su redacción aún puede cambiar en una versión posterior. Las palabras se eligen cortas donde la interfaz recorta una etiqueta (un beneficiario es `Destinatario` en español, una descripción `Notiz` en alemán).

**Colores.** La interfaz usa cuatro colores (verde para lo seleccionado y el foco, naranja para un aviso, rojo para un error, gris para lo secundario) y elige la pareja que conviene al terminal: le pregunta si su fondo es claro u oscuro. Donde el terminal no responde (algunos multiplexores, una sesión por ssh) puede equivocarse y dibujar texto pálido sobre fondo pálido. `theme = "dark"` o `theme = "light"` en `config.toml` lo corrige, y `theme = "auto"` (el valor por defecto) sigue al terminal. En la interfaz, `ctrl+t` abre la lista: al moverte por ella se prueba cada tema en la pantalla al momento, `enter` se queda con uno y escribe `theme = "…"` en `config.toml` (cambiando solo esa línea, como hace el idioma; si el archivo no se puede escribir, el tema cambia igualmente hasta que salgas, y la línea de estado lo dice), y `esc` vuelve al que estaba en uso. La línea de muestra de cuatro puntos enseña los colores. Un tema solo cambia colores: la selección es vídeo inverso y el resto del énfasis es negrita, así que nada depende solo del color, y con la variable de entorno `NO_COLOR` la interfaz se dibuja sin ningún color. Un tema desconocido en el archivo se rechaza con un mensaje que lista los que hay.

**Funciones sin terminar.** Una historia que se integra antes de estar terminada queda desactivada hasta que `config.toml` la activa, en una tabla `[features]` (`some_feature = true`). Así una historia sin terminar no retrasa una versión. Un nombre que no existe se rechaza, y el error lista los que existen. En esta versión no hay nada tras un indicador.

Volver a importar el mismo extracto, o uno que se solapa, es seguro: cada fila recibe un hash estable (cuenta, fecha, importe, otra parte, IBAN, concepto, texto de contabilización). Dos movimientos realmente idénticos el mismo día se numeran, así que se conservan los dos. Las filas que el banco marca como *Umsatz vorgemerkt* (pendiente) se ignoran hasta que se contabilizan.

## Interfaz del terminal

`thaler` a secas (sin argumentos) abre una interfaz organizada como lazygit: paneles a la izquierda y, a la derecha, un panel de detalle que muestra lo que esté seleccionado.

(La captura está en inglés; en español la interfaz dice Inicio, Cuentas, Transacciones, Patrimonio neto, etc.)

La franja de arriba cambia entre **pantallas**, y el periodo a su derecha (`[ oct 2026 ]`) se aplica a todas. Empieza en el mes actual.

| Pantalla | Tecla | Qué muestra |
| --- | --- | --- |
| Libro | `L` / `F1` | los tres paneles de abajo: las cuentas y el historial de transacciones del periodo |
| Presupuesto | `B` / `F2` | ingresos y gastos por categoría del periodo, con barras de proporción; los meses a la izquierda. Para un mes, las categorías con objetivo muestran lo gastado, el objetivo y lo que queda (en rojo una vez superado), y `tab` pasa a las categorías, donde `enter` muestra las transacciones que hay detrás de la cifra de una categoría; `e` fija o quita un objetivo y activa o desactiva el arrastre de una categoría (véase más abajo) |
| Previsión | `F` / `F3` | tus programaciones y cuándo vence la siguiente de cada una, y un aviso para una cuenta que bajaría de su mínimo; `tab` cambia a los saldos de cada cuenta semana a semana, `a` a una cuenta cada vez |
| Informes | `R` / `F4` | lo que gastó cada categoría en los 12 meses hasta el que se muestra (hasta este mes para todo el tiempo): una lista de las categorías, cada una con un pequeño gráfico de sus meses y su total, y, para la seleccionada, sus meses como barras con el total y la media mensual. `↑`/`↓` eligen la categoría (la primera línea es todo el gasto), y `[` `]` `t` `T` mueven los 12 meses. **`tab`** cambia al segundo informe, ingresos frente a gastos: una línea por mes con lo que entró, lo que salió, lo que se ahorró y qué parte de los ingresos es (negativa cuando salió más de lo que entró, un guion para un mes sin ingresos), una barra de cuánto de los ingresos se gastó (llena y terminada en `!` cuando fue más) y el total; `↑`/`↓` desplazan los meses. **`tab` otra vez** muestra los destinatarios: una línea para cada uno, el que más se llevó primero, con una barra frente al mayor, lo que se llevó, su parte de todo el gasto y cuántas transacciones fueron (los destinatarios se distinguen sin tener en cuenta mayúsculas ni espacios, las transacciones sin destinatario son una línea, una devolución cuenta contra su destinatario, y a partir de 100 destinatarios el resto es una línea); `↑`/`↓` desplazan. **Un tercer `tab`** muestra el patrimonio neto: una línea por mes con lo que valían las cuentas el último día (todo lo contabilizado hasta entonces), cuánto cambió respecto al mes anterior y una barra frente al mes más alto (`▒` por debajo de cero); el saldo de cada cuenta se cuenta al tipo de cambio de ese día, así que introducir un tipo después no mueve un mes pasado, y un mes anterior al primer tipo de una moneda usa el tipo del final del rango; `↑`/`↓` desplazan, y un cuarto `tab` vuelve a las categorías. **`r`** elige los meses que cubren los informes: Desde y Hasta como `YYYY-MM` (como mucho 120 meses; un Hasta vacío es este mes, un Desde vacío es 11 meses antes del Hasta, y ambos vacíos vuelven a los 12 meses hasta el que se muestra). Un rango elegido se marca en el encabezado y se mantiene cuando `[` `]` mueven el mes que se muestra; un rango de más de 12 meses se dibuja con una celda del gráfico para varios meses, y las barras de una categoría muestran los meses más recientes y dicen cuántos quedan fuera, sin que el total ni la media salgan de la vista. **`e`** guarda el informe que se muestra como archivo CSV para una hoja de cálculo, para los meses que cubre: das un nombre de archivo o una carpeta (se propone `thaler-categories-2025-11-2026-10.csv`, en la carpeta desde la que se inició Thaler), y un archivo que ya existe nunca se sobrescribe. El archivo es sencillo a propósito: nombres de columna en inglés, importes en la moneda base como decimales simples con punto, meses como `YYYY-MM`, proporciones como porcentajes con dos decimales; una línea por categoría, mes o destinatario, y una línea `Total` para los dos primeros (el archivo de destinatarios contiene todos, no solo los cien primeros; el de patrimonio neto es `month,currency,net_worth`), y un nombre que una hoja de cálculo leería como fórmula lleva un `'` delante. Lo que un informe dejó fuera por falta de tipo de cambio queda fuera del archivo, y la línea de estado lo dice. Un mes con una devolución la cuenta contra el gasto (un guion en el gráfico, `▒` en las barras), y el gasto en una moneda sin tipo de cambio se deja fuera y se dice |

**Paneles del Libro**

| Panel | Columna izquierda | Panel derecho mientras tiene el foco |
| --- | --- | --- |

**Anotar un gasto** está pensado para pocas pulsaciones. Pulsa `a`:

```
importe ⏎   destinatario ⏎   categoría ⏎        p. ej.   8.40 ⏎  rew ⏎  ⏎
```

- La **cuenta** es la seleccionada en el panel de Cuentas. Con "Todas las cuentas" seleccionado es la última que usaste (en esta sesión o, si no, la de la transacción más reciente de la base de datos). Los importes están en la moneda de esa cuenta, así que no hay moneda que escribir.
- **Importe:** `12.50` es un gasto, `+2450` es un ingreso.
- **Destinatario** es el título que tiene la transacción en la lista (cámbialo después con `r`): al escribir el principio de un destinatario conocido se resalta, y Enter lo completa. `↑` descarta la sugerencia si querías algo nuevo.
- **Categoría:** primero se ofrece la categoría a la que fue ese destinatario la última vez (marcada "mismo destinatario"), después la de destinatarios que se le parecen (marcada "destinatario parecido"), y luego las categorías del tipo adecuado según cuánto las usas. Escribe para filtrar, o escribe un nombre nuevo completo como `Expenses:Gifts`. La última entrada, "decidir luego", la apunta sin categoría.
- **Descripción** es opcional y va después de la fecha (`tab` desde allí; no estorba en el camino rápido de arriba). Úsala para una nota sobre para qué fue la transacción. Se muestra junto a la transacción, `/` busca en ella, y en una fila importada empieza siendo el concepto del banco, que puedes editar o borrar.
- **Fecha**: por defecto hoy; `y` es ayer, `-2` es hace dos días, o escribe `2026-10-20` / `20/10/2026`. Los errores se señalan en el formulario y no se escribe nada.

**Moverse por el formulario.** La línea bajo el formulario dice qué hace `Enter` en el campo en que estás. Añadir está pensado para ser rápido, así que ahí `Enter` en la *categoría* guarda; en los demás casos `Enter` avanza, y al editar recorre todos los campos y guarda en la *descripción*, de modo que a todos se llega solo con `Enter`. Para volver atrás, pulsa `↑` (en el importe, la fecha y la descripción, `↑`/`↓` pasan de un campo a otro; en las listas de destinatario y categoría `↑` primero recorre las sugerencias y luego vuelve atrás) o `shift+tab`; `tab` avanza. `ctrl+s` guarda desde cualquier sitio y `esc` cancela.

**Crear una cuenta** no necesita la línea de comandos. Pulsa `n`, escribe un nombre (`Sparkasse` se convierte en `Assets:Sparkasse`), elige Activos o Pasivos y confirma la moneda (empieza siendo tu moneda base). Si ya sabes lo que tiene la cuenta, rellena **Saldo** y **A fecha**; déjalos vacíos para empezar de cero.

**Mover dinero entre tus cuentas.** Pulsa `x`. Escribe el importe; las cuentas empiezan siendo la seleccionada y otra con la misma moneda, y `tab` y luego `◂ ▸` las cambian (elegir la cuenta del otro campo intercambia las dos). Cuando las cuentas tienen monedas distintas aparece un campo *Recibido*: escribe lo que llegó de verdad, lo que fija el tipo de cambio que obtuviste (`1 EUR = 1.0850 USD` se muestra mientras escribes). Una transferencia se apunta como dos transacciones enlazadas, una en cada cuenta, como las dos líneas de tus extractos: van a `Equity:Transfers` (o `Equity:Conversions` entre monedas), así que una transferencia no es ni ingreso ni gasto. **`e` en cualquiera de las dos mitades edita la transferencia como una sola cosa**: se abre la misma ventana, titulada con los dos números y rellenada, y el importe, lo que llegó, la fecha y las dos cuentas cambian en ambas mitades a la vez; conservan sus números y siguen siendo una transferencia. Cuando el banco contabilizó las dos mitades en días distintos, la mitad que llega conserva su propio día salvo que cambies la fecha (la ventana dice qué día es). Un destinatario que escribió Thaler sigue a una cuenta nueva; uno del banco se queda. **`d` en cualquiera de las dos mitades borra ambas**, tras mostrar las dos; las transacciones marcadas que incluyen una mitad se llevan la otra. `z` deshace una transferencia nueva, un cambio o un borrado, y una transferencia borrada vuelve enlazada. **Enlazar dos que ya tienes.** El dinero que moviste tú a menudo llega como dos transacciones normales, introducidas a mano o importadas antes que la otra cuenta. `l` en una de ellas lista lo que podría ser su otra mitad: transacciones en otra de tus cuentas que mueven el importe opuesto y no son ya una transferencia, la más cercana en fecha primero; `enter` enlaza la elegida, y ambas se apuntan en `Equity:Transfers` y se marcan con `⇄`, así que el movimiento no es ni gasto ni ingreso. Para enlazar dos que la lista no ofrece (entre monedas, donde los importes difieren), márcalas con `space` y pulsa `l`: dentro de una moneda tienen que mover el mismo importe, una salida y una entrada, y entre monedas van a `Equity:Conversions`. `l` en una mitad de una transferencia desenlaza las dos, que quedan esperando en Sin categoría. `z` deshace un enlace o un desenlace. En la línea de comandos: `thaler cli transfer link A B` y `transfer unlink ID`. `r` sigue abriendo el formulario normal en una mitad, para renombrarla o darle una nota. Recategorizar una mitad con `c`, o cambiar ahí su importe, sigue deshaciendo la pareja. En la línea de comandos: `thaler cli transfer --from A --to B --amount N [--to-amount M]`. **Cambiar o borrar una transferencia entera:** `thaler cli transfer edit ID` cambia las dos mitades a la vez, dado el número de cualquiera de ellas: solo cambian las opciones que das (`--from`, `--to`, `--amount`, `--to-amount`, `--date` para las dos mitades, `--in-date` para la mitad que llega, `--memo` para las dos descripciones), y las mitades conservan sus números y siguen siendo una transferencia. Un destinatario que escribió Thaler (`Transfer to Savings`) sigue a una cuenta nueva; un destinatario y un texto del banco se quedan. `thaler cli transfer delete ID` lista las dos mitades y, con `--yes`, borra ambas, o ninguna cuando una está en una cuenta cerrada. Borrar una mitad sola y recuperarla con `z` la vuelve a enlazar con la otra. Importar después los extractos del banco toma las dos mitades (véase más abajo) en lugar de añadirlas otra vez.

**Renombrar y cerrar cuentas.** `thaler cli account rename Assets:Bank Assets:Sparkasse` da un nombre nuevo a una de tus cuentas (Activos o Pasivos); el nombre nuevo conserva el tipo y no puede estar ocupado, y todo lo que pertenece a la cuenta (transacciones, programaciones, su saldo mínimo) sigue perteneciéndole, porque cada una de esas cosas se refiere a la cuenta y no a su nombre. `thaler cli account close Assets:Old` aparta una cuenta cuando ya no la usas: no puede tener nada, en ninguna moneda (mueve antes lo que tenga a otra cuenta), y ninguna programación puede apuntar en ella, así que cerrar nunca esconde dinero ni deja una programación que no se pueda confirmar; un rechazo dice cuál. Una cuenta cerrada conserva su historial: sus transacciones se quedan, un informe de saldos a un día en que estaba en uso sigue contando lo que tenía, y el patrimonio neto de esos meses no cambia. Se marca `closed` en `account list`, queda fuera de la previsión y no acepta nada nuevo: ninguna transacción, transferencia, importación, saldo inicial ni programación puede apuntar en ella, y sus transacciones no se pueden editar ni borrar (su categoría sí se puede cambiar), hasta que `thaler cli account reopen` la recupera. `account list --json` da a cada cuenta un campo `closed`. En la interfaz se hace lo mismo en el panel de Cuentas (`2`): `r` pide el nombre nuevo de la cuenta seleccionada (escribes lo que sigue al tipo, `Sparkasse` para `Assets:Sparkasse`; un nombre ocupado, de otro tipo o que no es un nombre se indica en la ventana y no cambia nada), y `c` la cierra, diciendo por qué no cuando tiene dinero o una programación apunta en ella. Una cuenta cerrada desaparece del panel, de los formularios y de la lista de transferencias; `v` muestra las cuentas cerradas después de las demás, atenuadas y marcadas `cerrada`, con sus transacciones como historial, y `c` en una de ellas la reabre. Una transacción de una cuenta cerrada no se puede editar ni borrar (la línea de estado dice que reabras la cuenta), pero su categoría se puede cambiar con `c` como antes. `z` deshace un cambio de nombre, un cierre o una reapertura.

**Filtrar y ordenar las transacciones.** El Libro ya acota su lista por la cuenta seleccionada en el panel de Cuentas (`2`), por el mes que se muestra (`[` `]`, `t`, `T`), por `u` (solo lo que necesita categoría) y por la búsqueda (`/`). `f` añade más: un importe mínimo y uno máximo, una primera y una última fecha, parte del nombre de una categoría, y el orden. El importe es el tamaño de la transacción en tu propia cuenta, vaya el dinero en el sentido que vaya (un gasto de 12.00 y un ingreso de 12.00 son ambos 12.00), los extremos se incluyen, y en un libro con varias monedas cada transacción se compara en la suya (15 significa 15 dólares para una cuenta en dólares y 15 euros para una en euros). Una fecha se escribe como la escribe el idioma, o `YYYY-MM-DD`, y cualquiera de los extremos puede faltar: las fechas sustituyen al mes que se muestra en el Libro (la barra de arriba dice `2026-09-01 – 2026-09-30`, `desde 2026-10-04` o `hasta 2026-09-16`; las demás pantallas conservan el mes). La categoría se compara como en la búsqueda, por letras en orden: `groc` encuentra `Expenses:Groceries`, y una transacción cuenta cuando alguna de sus categorías coincide. El orden se elige en el último campo con `←` `→`: fecha (lo más nuevo primero, como antes, o lo más antiguo primero), importe (el mayor o el menor primero), destinatario o categoría, de la A a la Z. Todo funciona junto con la cuenta, el mes, `u` y la búsqueda. El panel de Transacciones dice `filtrado` y `ordenado` en su título, y la línea de estado cuántas transacciones coinciden. Un problema (un importe que no es un número, un mínimo por encima del máximo, fechas al revés) se indica en la ventana y no cambia nada; `ctrl+x` ahí quita el filtro, igual que `esc` en la lista (el orden se queda, porque es una preferencia). La cuenta se filtra seleccionándola en el panel de Cuentas, como antes.

**Varias transacciones a la vez.** En el panel de Transacciones, `space` marca la que está bajo el cursor (un `✓` en lugar de su signo habitual, y el título del panel dice cuántas hay marcadas) y baja, así que una serie es `space space space`; `ctrl+a` marca todo lo que se ve, y otra vez lo suelta todo. `c` pide entonces una categoría para todas las transacciones marcadas, `enter` las pone ahí, y `d` lista lo que se va a ir (las primeras y cuántas más) y pregunta antes de borrarlas. Las dos cosas son todo o nada: si una de ellas no se puede cambiar (una transferencia o una transacción dividida no se pueden recategorizar aquí; una transacción de una cuenta cerrada no se puede borrar) no cambia ninguna, y la línea de estado dice por qué. `z` deshace todo el grupo de una vez, con las transacciones de vuelta con sus números antiguos. Una marca solo está en una transacción que puedes ver: una búsqueda, un filtro, otra cuenta u otro mes la ocultan y la marca se va con ella, así que lo que se categoriza o se borra es siempre lo que está en pantalla. `esc` suelta las marcas (antes de borrar la búsqueda o el filtro). Una regla se hace a partir de un destinatario, así que la ventana de categoría de varias transacciones no tiene campo de regla; con una sola transacción marcada, `c` y `d` actúan sobre ella esté donde esté el cursor, y la ventana es la habitual.

**Dividir una transacción.** Un pago es a menudo varias cosas: un tique de la compra que es comida y artículos del hogar, una nómina que es sueldo y una paga extra. `s` en una transacción abre la ventana de división (también `ctrl+o` en el formulario de añadir o editar, que se lleva lo que escribiste, así que una división nueva empieza con `a`). Tiene la cuenta, el importe (con `+` para un ingreso), el destinatario, la fecha y la descripción, como el formulario, y debajo las líneas, cada una una categoría y su parte del importe, escrita sin signo. Escribe unas letras de una categoría y `↑` `↓` eligen, como en la lista de categorías, o un nombre nuevo completo como `Expenses:Gifts`. Una línea puede quedarse sin importe y se lleva lo que dejan las demás; la ventana dice lo que queda por repartir, o en cuánto se pasan las líneas. `tab` recorre los campos, `ctrl+n` añade una línea bajo la que estás, `ctrl+x` la quita, `ctrl+s` guarda. Guardar se rechaza hasta que las líneas suman el importe, y antes no se escribe nada: la transacción es un solo apunte en tu cuenta con un asiento por categoría, así que cada informe y el presupuesto cuentan la parte de cada categoría. Una división se muestra como `»` en la lista; `e` o `r` en una abre la misma ventana, y `z` deshace el cambio. Una transacción con una sola línea vuelve a ser una transacción normal. Solo se puede dividir una transacción de tu propia cuenta con categorías de ingresos o gastos: una transferencia entre tus cuentas no, y la transacción de una cuenta cerrada no se puede editar. Una división no se puede categorizar con `c` (eso es para una categoría), ni tampoco las transacciones marcadas que incluyen una. El propio Thaler comprueba cada división que escribe, desde la ventana o desde `thaler cli split`: una cuenta tuya, categorías de ingresos o gastos que se llevan cada una una parte en la moneda de la cuenta, y partes que suman el importe.

**Cuadrar con el saldo de tu banco.** Una importación solo trae movimientos, así que el saldo de una cuenta es incorrecto hasta que Thaler sabe dónde empezó. Selecciona la cuenta y pulsa `b`, y escribe lo que muestra tu banco en un día dado. Thaler apunta la diferencia como una transacción de *saldo inicial* contra `Equity:Opening`, fechada el día antes de la primera transacción de la cuenta, para que todo el historial cuadre. Pulsa `b` otra vez después de la siguiente importación y corrige esa misma transacción en lugar de añadir otra. Para una tarjeta de crédito o un préstamo, escribe lo que debes (una tarjeta que muestra 500.00 de deuda es `500`). `z` deshace el cambio. En la línea de comandos: `thaler cli account balance ACCOUNT AMOUNT --as-of DATE`.

**Importar un extracto del banco** también funciona desde la interfaz. Pulsa `i`:

- **Archivo:** se listan los extractos de `~/Downloads` (archivos CSV, OFX y QIF, por sus nombres `.csv`, `.ofx`, `.qfx` y `.qif`), lo más nuevo primero, así que el extracto que acabas de descargar ya está resaltado. Escribe unas letras para acotar la lista, o pega o arrastra la ruta de un archivo al campo. Escribe o suelta la ruta de una *carpeta* (por ejemplo `~/Desktop`) para listar en su lugar los extractos de esa carpeta. Para listar siempre otra carpeta, pon `import_dir = "~/Documents/bank-exports"` en `config.toml`.
- La **cuenta** (por defecto, la seleccionada en el panel de Cuentas) y el **perfil** se cambian con `tab` y `←` `→`. El perfil empieza en **auto**: Thaler lee la cabecera del archivo resaltado (o escrito) y elige el perfil cuyas columnas tiene, mostrado como `auto: sparkasse` y otra vez en la revisión (`perfil sparkasse`), así que un archivo de otro banco se lee con tu propio perfil para él (véase `config.example.toml`) sin elegir nada. Un perfil encaja cuando el archivo tiene las columnas de fecha e importe que nombra; gana el que nombra más columnas del archivo (uno que lista todas las columnas del extracto de un banco gana a uno que lista dos), y entre iguales los tuyos de `config.toml`, en el orden en que están escritos, van antes que los incluidos. Cuando no encaja ninguno, `enter` lo dice en lugar de adivinar, y `←` `→` eligen un perfil a mano, que entonces se usa tal cual, aunque el archivo no se le parezca, y es el que se ofrece la próxima vez (`auto` sigue siendo `auto`). `thaler cli import` encuentra el perfil del mismo modo salvo que `--profile` nombre uno.
- `enter` muestra una **revisión** y no escribe nada: cuántas filas son nuevas, cuántas se importaron antes, con cuántas no coincidió ninguna regla, y cada fila con la categoría que eligieron las reglas. Un segundo `enter` importa. Si algunas filas no se pueden leer, se listan y `y` importa el resto.
- **`c` cambia la categoría de la fila bajo el cursor** antes de que se escriba nada, en la misma lista que en todas partes (escribe para acotarla, o un nombre completo como `Expenses:Gifts` para crear una nueva; `enter` elige, `esc` la deja como estaba). Tu elección gana a las reglas y a la categoría de una programación, se marca con `✎` en la revisión y es lo que escribe la importación; `r` vuelve a lo que eligieron las reglas, y leer el archivo otra vez olvida todas las elecciones. La revisión se recalcula cada vez, así que los recuentos acompañan: una fila que categorizas deja de contar como sin categoría, y una fila que pones en `Equity:Transfers` se empareja con la otra mitad como cualquier transferencia, mientras que una que pones en otro sitio no. Elegir `Sin categoría` deja la fila para más tarde. Una fila que se importó antes, o que toma una entrada tuya, conserva su categoría (la línea bajo la lista dice por qué). No se guarda nada para una regla: para que la elección sea una regla la próxima vez, añade una en `config.toml` o categoriza la fila con `c` después de importar.
- Después se muestran las filas sin categoría de la cuenta, listas para `c`, y `z` deshace toda la importación.
- **Se nota un extracto nuevo.** Mientras Thaler está abierto mira la carpeta de importación cada pocos segundos, y cuando llega un extracto que no estaba antes (el que acabas de descargar, o uno guardado de nuevo con el mismo nombre) la barra inferior dice `nueva exportación umsaetze.csv · i la importa`, o cuántos han llegado. El archivo ya está resaltado cuando pulsas `i`, que además quita el mensaje; con la lista de archivos abierta se añade a la lista al momento. Lo que estaba en la carpeta cuando Thaler arrancó, o cuando cambió `import_dir`, no es nuevo, y solo aparece un mensaje por archivos que se ven llegar. Solo se leen los nombres, tamaños y horas de los extractos, nunca lo que contienen, y no se importa nada hasta que lo digas. `watch_import_dir = false` en `config.toml` lo desactiva.
- **`I` lista las importaciones que hiciste**, la más nueva primero: cuándo, la cuenta y el archivo, y bajo la lista lo que hizo la que está bajo el cursor (filas añadidas, entradas tuyas con las que coincidió, transferencias que emparejó, fechas de programaciones a las que respondió, el perfil). `enter` la deshace entera, tras decir lo que se irá. Funciona con cualquier importación, no solo con la última, y también con una hecha con `thaler cli import`. Borra las transacciones que añadió la importación, vuelve a hacer manuales las entradas tuyas que tomó, devuelve las otras mitades de las transferencias que emparejó a la categoría que tenían (una que hayas cambiado desde entonces se queda como la dejaste), y vuelve a poner como pendiente una fecha de una programación a la que respondió. Lo que cambiaste desde entonces en las transacciones borradas (una categoría, una nota) se va con ellas, y `z` no las recupera: para eso, importa el archivo otra vez. Una importación cuya cuenta se ha cerrado se rechaza. Un registro guarda el nombre del archivo, no la carpeta, y el perfil; las importaciones hechas antes de que existiera esta lista no están en ella.

**Las entradas que hiciste a mano no se añaden dos veces.** Si apuntas tus gastos tú y más tarde importas el extracto, cada fila del banco se compara con lo que escribiste: la misma cuenta, exactamente el mismo importe, con fecha dentro de tres días, una entrada normal (una cuenta, una categoría) que todavía no se ha asociado a una fila del banco. Cuando se encuentra una, la fila *toma* esa entrada. No se añade nada; la entrada solo recuerda qué fila del banco es, así que importar el archivo otra vez la reconoce. Tu destinatario, tu fecha y tu categoría se quedan como los escribiste, elijan lo que elijan tus reglas. La revisión muestra estas filas como `↔ #12 REWE` antes de escribir nada, cada entrada se toma como mucho una vez (la fecha más cercana primero), y `z` la vuelve a soltar. Esto funciona también con las dos mitades de una transferencia que introdujiste con `x`. Las entradas que son divisiones, que mueven dinero entre dos de tus cuentas en una sola transacción o que son un saldo inicial nunca se asocian.

**Objetivos mensuales.** En la pantalla de Presupuesto, elige un mes y pulsa `e`: una ventana lista tus categorías de gasto con el objetivo que tiene cada una ese mes. Muévete con `↑` `↓`, escribe un importe y `enter` lo guarda; un importe vacío quita el objetivo, y `z` deshace un cambio. Un objetivo pertenece a un mes (cada mes conserva el suyo, así que cambiar el del mes siguiente no toca este) y está en la moneda base; la ventana los fija en categorías de gasto (una categoría de ingresos también puede tener uno, véase Ingresos previstos más abajo). Para ese mes el Presupuesto muestra el objetivo total y lo que queda, y bajo cada categoría con objetivo lo gastado, el objetivo y lo que queda, o en cuánto se superó, con la barra y el importe en rojo. El gasto en categorías sin objetivo se lista aparte y no resta de lo que queda de las categorías planificadas. `c` empieza el mes que se muestra a partir del anterior: añade los objetivos que le faltan y conserva los que tiene, así que no se sobrescribe nada, y `z` deshace exactamente lo que añadió. Todo el tiempo no tiene objetivos: elige un mes.

**Grupos de categorías.** Las categorías que cuelgan unas de otras forman un grupo: `Expenses:Housing:Rent` y `Expenses:Housing:Power` están en `Expenses:Housing`, y también otras más profundas como `Expenses:Housing:Utilities:Water` (un grupo es el primer nivel bajo el tipo; una categoría con el nombre del grupo, `Expenses:Housing` en sí, cuenta como uno de sus miembros en cuanto hay una por debajo). Un grupo no tiene nada propio que fijar: su objetivo es la suma de los objetivos de sus categorías, así que fijar, quitar y copiar objetivos funciona como antes y nada se cuenta dos veces. El servicio suma cada grupo del mes (`MonthBudget.Groups`: gastado, objetivo, arrastrado, restante, y lo que gastaron las categorías sin dinero reservado, que, como las cifras del propio mes, se mantiene aparte de lo que queda), y los grupos junto con las categorías que no están en ninguno suman los totales del mes. `thaler cli budget` los muestra en una segunda tabla bajo las categorías, y `--json` los tiene como `groups`. La pantalla de Presupuesto los muestra: en un mes, cada grupo es una fila que suma sus categorías, con las categorías debajo, y `space` pliega un grupo para que solo se vea su fila (véase más abajo).

**Plegar un grupo en el Presupuesto.** Con las categorías enfocadas (`tab`), un grupo es una fila propia, marcada `-` mientras sus categorías se muestran debajo y `+` mientras está plegado: su nombre, lo que gastó el grupo, una barra, la suma de sus objetivos y lo que queda, como una categoría con objetivo. Le siguen sus categorías, sangradas, con su nombre sin el del grupo (`Rent` bajo `Housing`), una categoría sin objetivo como una línea, y la que tiene el nombre del grupo como `Housing (directamente)`. Un grupo que tiene una categoría con objetivo se lista con los objetivos, con todas sus categorías; uno que no tiene ninguna se lista con los demás sin objetivo. `space` pliega el grupo en el que está la selección, o lo despliega cuando está plegado, `←` pliega el grupo, o va de una categoría a su grupo, y `→` lo despliega; `↑` `↓` se saltan un grupo plegado. `enter` en un grupo abre el Libro con las transacciones de todas sus categorías (el nombre del grupo en el título de Transacciones), y en una categoría con las suyas, como antes. Todo el tiempo y los meses sin objetivos se agrupan igual. Los pliegues se mantienen mientras Thaler está abierto, no en `config.toml`.

**Las transacciones detrás de una cifra.** En el Presupuesto, `tab` pasa de los meses a las categorías (el mismo panel que muestra las cifras, con su propia marca `▸`, desplazándose cuando hay más de las que caben), `↑` `↓` eligen una, y `enter` abre el Libro con sus transacciones: el mes que se muestra, todas las cuentas, y la categoría en el título del panel. Es la misma lista de la que salió la cifra, así que puedes editar, recategorizar o borrar desde ahí, y `esc` vuelve a mostrarlo todo. `tab` o `esc` vuelven a los meses.

**Ingresos previstos.** Una categoría de ingresos también puede tener objetivo: lo que planeas recibir de ella ese mes. En la ventana de objetivos (`e`) las categorías de ingresos siguen a las de gasto, marcadas `+`, y el campo se llama Previsto en lugar de Objetivo; `tab` no hace nada ahí, porque los ingresos no tienen nada que arrastrar. En la línea de comandos es `thaler cli budget set Income:Salary 3000 --month 2026-10`. Para un mes con plan el Presupuesto muestra **Ingreso previsto** y **Sin asignar**: el ingreso previsto menos los objetivos de las categorías de gasto, en rojo cuando los objetivos suman más que el plan. Bajo Ingresos, cada categoría prevista muestra lo que ha entrado frente al plan (`de 3000.00 · faltan 100.00`, o `400.00 más de lo previsto`); las demás se listan como antes. `c` copia los planes hacia delante con los demás objetivos. `thaler cli budget` también los lista: para un mes con ingresos previstos añade una tabla de ingresos (recibido, previsto y por llegar, negativo una vez superado el plan) y una línea "Unassigned: … (planned income … less targets …)"; sin plan la salida es como antes.

**Transacciones recurrentes.** Una programación es una transacción que se repite: el alquiler cada mes, una nómina el día 28, un seguro cada año. La pantalla de Previsión (`F`) las lista, la que vence antes primero, con lo que mueve cada una y cuándo vence la siguiente; `↑`/`↓` las recorren. Una fecha a la que nadie ha respondido todavía se marca con `!` y se cuenta encima de la lista, y una programación pausada o que ha terminado lo dice. **`n`** crea una nueva y **`e`** cambia la seleccionada, en una ventana como los demás formularios (`tab` y `enter` avanzan, `ctrl+s` guarda, `esc` cancela): un nombre, un importe (sin signo es dinero que sale, `+` dinero que entra), la cuenta en la que se mueve y a dónde va, que escribes y eliges de la lista de tus categorías y otras cuentas. Elige una de tus cuentas y se convierte en una transferencia, que pregunta lo que llega cuando las dos tienen monedas distintas. Luego con qué frecuencia (cada N semanas, meses o años), la primera fecha, una última fecha opcional y, para lo que no es una transferencia, una tolerancia en porcentaje para recibos que varían. Lo que se apunta lleva el nombre de la programación. **`p`** pausa la programación seleccionada, o la reanuda, y `z` deshace cualquiera de estas cosas. Una programación con varios asientos solo se puede cambiar a través del servicio, no aquí. **`enter`** recorre lo que vence, la fecha más antigua primero, una a una (las mismas fechas que `thaler cli schedule due`). Thaler solo pregunta: `enter` apunta la fecha tal cual, en su propio día, `e` la apunta por el importe que fue de verdad (para un recibo que varía, o cuando lo que llegó es distinto), `s` la salta, `↑`/`↓` miran otra fecha y `esc` para. Tras cada respuesta aparece la fecha siguiente, hasta que no queda ninguna. Una transferencia se apunta como las dos transacciones enlazadas de `x`. `z` deshace la última respuesta: un apunte se borra y un salto se levanta, así que la fecha vuelve a vencer. `schedule add Rent --unit month -a Assets:Bank --amount=-900 -t Expenses:Rent --start 2026-11-28` define una, `--every 2` la hace cada dos semanas, meses o años, y una programación que empieza el día 31 cae en el último día de los meses más cortos. **Thaler nunca apunta una por sí solo.** `schedule due` lista las fechas hasta hoy que aún no tienen respuesta, y cada una se responde con `schedule confirm ID DATE` (apuntada en ese día, `--amount=-950` para otro importe) o `schedule skip ID DATE` (no se apunta nada). Una fecha respondida no vuelve; si borras la transacción que apuntó una confirmación, su fecha vuelve a vencer. **Una fila importada del banco liquida la fecha a la que pertenece:** una fila en la cuenta de la programación por exactamente su importe, con fecha dentro de tres días de una fecha sin responder, responde esa fecha (la más cercana, si hay dos a mano) y se apunta en la categoría de la programación salvo que una de tus reglas elija otra; la importación lo dice (`Settled 2026-08-28 of the schedule Rent`), `--dry-run` las cuenta, y deshacer la importación (`u` en la interfaz) vuelve a poner la fecha como pendiente. Una fila que toma una entrada que hiciste a mano deja la programación en paz, así que salta tú esa fecha. `schedule edit ID` cambia solo las opciones que das, `schedule delete ID` quita una programación y conserva lo que apuntó, y `schedule` a secas las lista. **Recibos que varían:** para la luz, da el importe habitual y una tolerancia: `schedule add Electricity --unit month -a Assets:Bank --amount=-80 -t Expenses:Power --tolerance 25` (`edit ID --tolerance 0` la vuelve exacta). Una fila del banco dentro de un 25 % de 80.00, por encima o por debajo, en el mismo sentido, sigue liquidando su fecha, y lo que se apunta es lo que dice el banco. Las listas muestran ese importe como `~-80.00 EUR`. Confirmar una fecha a mano admite `--amount` como en cualquier programación, sea cual sea la tolerancia. Una transferencia programada no tiene tolerancia. **Transferencias:** una programación puede mover dinero entre tus propias cuentas, como un ahorro mensual: `schedule add Saving --unit month -a Assets:Bank --amount 200 --to Assets:Savings` (`-a` es la cuenta de la que sale, `--to` aquella a la que llega; entre monedas, `--to-amount` dice cuánto llega). Confirmar una fecha apunta una transferencia, las dos transacciones enlazadas de `thaler cli transfer`, y `--amount` y `--to-amount` cambian lo que se mueve en esa fecha. Una fila del banco del mismo importe en cualquiera de las dos cuentas liquida la fecha y se apunta en `Equity:Transfers`; la fila de la otra cuenta se empareja entonces con ella como siempre. **Terminar y pausar:** `--end DATE` (en `add` o `edit`; `--end none` lo quita) es el último día en que puede caer una fecha. `schedule pause ID` hace que deje de proponer nada desde hoy y `schedule resume ID` la vuelve a poner en marcha desde hoy; las fechas que cayeron entre medias se descartan, no se guardan, y una fila del banco no liquida ninguna de ellas. Las fechas anteriores a una pausa que nadie respondió siguen pendientes. **Hacia dónde van los saldos:** `thaler cli forecast [--until DATE]` calcula lo que tendría cada cuenta si se confirmaran todas las programaciones: el saldo de hoy y luego, cada día que una programación lo mueve, lo que cambia y el saldo después (90 días por delante salvo `--until`). Una fecha que llegó sin respuesta cuenta hoy, una saltada o confirmada no cuenta, una programación pausada o terminada se detiene, y una transferencia mueve las dos cuentas, cada una en su moneda. Solo cuentan las programaciones: una compra que aún no has hecho no está, ni tampoco una transacción ya apuntada con una fecha futura. No se apunta nada. En la pantalla de Previsión, **`tab`** cambia de las programaciones a los saldos: para cada cuenta de activo y de pasivo lo que tiene hoy y lo que tendría al final de cada una de las próximas 13 semanas (la primera semana termina dentro de una semana), con lo que mueven las programaciones esa semana; `↑`/`↓` desplazan, `tab` vuelve. Un saldo por debajo del mínimo de la cuenta se marca con `!`, y los avisos siguen arriba. **`a`** limita la Previsión a una cuenta, la siguiente cada vez y todas otra vez después de la última, y el título dice cuál: sus programaciones (las que la mueven, una transferencia en cualquiera de sus cuentas), sus saldos y su aviso, y `enter` recorre solo las fechas de esas programaciones. Una programación nueva empieza en esa cuenta, y una guardada para otra cuenta vuelve a mostrarlas todas. **Un mínimo para una cuenta:** `thaler cli account minimum Assets:Bank 500` dice que la cuenta no debería bajar de 500.00 (`--amount=-300` para un descubierto acordado, `--clear` para quitarlo, sin argumentos para listarlos). `forecast` termina entonces con un aviso por cada cuenta que bajaría de él, con el primer día, el saldo de ese día y la programación que más le quita; de una que ya está por debajo se dice que está por debajo hoy. Los saldos se comparan al final del día, así que una nómina y un alquiler el mismo día se toman juntos. De una cuenta sin mínimo nunca se avisa, y solo una cuenta de activo puede tenerlo. En la pantalla de Previsión, **`m`** fija el mínimo de una cuenta en una ventana (las cuentas de activo se listan con el suyo; escribe un importe, o déjalo vacío para quitarlo; `enter` guarda, `esc` cancela, `z` deshace), y la pantalla dice, encima de las programaciones, qué cuentas bajarían del suyo en los próximos 90 días: el primer día, el saldo de ese día y la programación que más le quita, o que la cuenta ya está por debajo de su mínimo.

**Arrastre.** En la misma ventana, `tab` hace que la categoría bajo el cursor arrastre lo que le queda al mes siguiente, desde el mes que se muestra (ese mes empieza sin nada arrastrado). Lo que quedó entra como importe positivo, y lo que se gastó de más como uno negativo, así que el exceso se devuelve con los meses siguientes. Un mes sin objetivo entre medias sigue adelante, arrastrando lo que gastó. No se guarda nada para ello: el importe arrastrado se calcula al mostrarse, a partir de los objetivos y el gasto de los meses desde entonces (el gasto al tipo de cambio del día en que se hizo), así que editar o importar una transacción antigua nunca puede dejar una cifra desfasada. El Presupuesto muestra `de 50.00 · +70.00 de arrastre · quedan 110.00` para una categoría así y un total `Arrastre`; `z` deshace el cambio.

**Transferencias entre tus propias cuentas.** Importa tu cuenta corriente y tu cuenta de ahorro y la misma transferencia aparece en los dos extractos, una vez saliendo y otra entrando. Contada como gasto y como ingreso, inflaría los dos en la pantalla de Presupuesto. Por eso, cuando una fila nueva tiene exactamente el importe opuesto de una transacción en otra de tus cuentas, dentro de tres días, y ninguna está categorizada todavía, Thaler las empareja: las dos se apuntan en `Equity:Transfers` (así que no son ni ingreso ni gasto), se marcan con `⇄` y se enlazan entre sí. La revisión de la importación muestra `⇄ Bank` en una fila emparejada antes de escribir nada, y `z` deshace el emparejamiento junto con la importación. Funciona en cualquier orden, cada fila se empareja como mucho una vez, y una fila que una regla ya ha puesto en una categoría real (el alquiler, por ejemplo) se deja en paz. Añade una regla con la categoría `Equity:Transfers` para marcar una transferencia cuya otra mitad aún no se ha importado; el saldo de `Equity:Transfers` es lo que sigue esperando. Si recategorizas o cambias una mitad, la pareja se deshace y la otra mitad vuelve a sin categoría para que lo notes.

Las reglas y los perfiles se leen de `config.toml` cada vez que pulsas `i`, así que puedes editarlos en otra ventana e importar de nuevo.

**Renombrar y fusionar categorías.** `K` lista todas las categorías, primero las de gasto y las de ingresos marcadas `+`, cada una con su número de transacciones; el cursor empieza en la categoría de la transacción seleccionada en el Libro, o en la seleccionada en el Presupuesto. `r` (o `enter`) pide el nombre nuevo, escrito entero (`Expenses:Dining`) y del mismo tipo: se renombran la categoría y las que cuelgan de ella (`Expenses:Food:Out`), y sus transacciones, objetivos, arrastre y programaciones la siguen; `z` lo deshace. `m` pregunta con qué otra categoría de su tipo fusionarla y vuelve a preguntar antes de mover todas sus transacciones, programaciones, objetivos (un mes para el que la otra ya tiene objetivo conserva el de la otra) y arrastre (salvo que la otra tenga uno), y la quita; `z` no puede deshacer una fusión, y una categoría con categorías por debajo se rechaza hasta que esas se fusionen. Las reglas de `config.toml` que nombran la categoría no se cambian: la línea de estado dice cuántas lo siguen haciendo, para que puedas editarlas (`C`).

**Gestionar las reglas.** `M` lista las reglas de `config.toml` en el orden en que se comprueban (gana la primera que coincide), un texto a buscar entre comillas y una expresión regular entre barras, cada una con su categoría. `e` (o `enter`) edita la que está bajo el cursor: el texto que busca y su categoría, con `tab` pasando de uno a otro y `enter` guardando; un texto demasiado corto, una expresión que no compila o una categoría que no es un nombre se indican en la ventana y no se escribe nada. `<` y `>` adelantan o retrasan la regla un puesto, porque el orden decide qué regla gana, y `d` la borra tras preguntar. `z` deshace el último cambio, en la ventana o después de cerrarla, mientras nadie haya cambiado el archivo entre tanto; Thaler nunca escribe sobre un archivo que no escribió él. Solo se reescriben las líneas de la regla que cambia: tus comentarios, tus ajustes y las demás reglas se quedan como están, y un comentario justo encima de una regla (sin línea en blanco entre medias) se mueve con ella; un comentario en una de las líneas de la propia regla se pierde al editarla. Un archivo cuyas reglas no están escritas como tablas `[[rule]]` una tras otra (una lista, una cadena de varias líneas) se rechaza con un mensaje, y se edita con `C` como antes. Las transacciones que una regla ya categorizó no cambian al editarla ni al borrarla, y un orden nuevo tampoco las cambia. `a` aplica las reglas, tal como están ahora en el archivo, a las transacciones que siguen sin categoría (las que categorizó una regla o tú a mano nunca se tocan): primero dice cuántas recibirían categoría y pregunta; `enter` o `y` lo hace y `z` las devuelve, en la ventana o después de cerrarla. Es lo que hace `thaler cli recategorize`, y sirve para las reglas que escribiste o cambiaste después de que llegaran esas transacciones.

**Crear una regla mientras categorizas.** En el selector de categorías, pulsa `tab` para ir a un campo *Regla*. Empieza con el destinatario; recórtalo a la parte que importa (`REWE Markt GmbH Filiale 12` → `REWE`). Mientras escribes, el selector dice cuántas otras transacciones sin categoría atraparía. `enter` categoriza entonces esta transacción, añade la regla al final de `config.toml` y categoriza también las que coinciden. `z` deshace las categorías de una vez; la regla se queda en el archivo (pulsa `C` para quitarla). Solo se escribe el final del archivo, así que tus comentarios y el orden de tus reglas no se tocan. Las reglas se comprueban de arriba abajo y gana la primera que coincide, así que si una regla anterior ya decide otra cosa para este destinatario, el selector nombra esa regla y se niega, en lugar de añadir una que nunca podría aplicarse.

En el selector de categorías va primero la categoría que usaste la última vez para el mismo destinatario (marcada "mismo destinatario"). Justo después (o primero, si el destinatario es nuevo) va la categoría de los destinatarios que se le parecen (marcada "destinatario parecido"): los bancos escriben una misma tienda de muchas maneras ("REWE SAGT DANKE 4711", "REWE Markt Berlin"), así que Thaler compara las palabras del destinatario, sin tener en cuenta números, formas jurídicas (GmbH) ni palabras de contabilización (Kartenzahlung), y da más peso a una palabra que tienen pocos de tus destinatarios (REWE) que a una que comparten muchos (Deutsche, Berlin), para que "Deutsche Bahn" no tome prestada la categoría de "Deutsche Bank". Es solo una sugerencia, puesta primero para que `c` `enter` la tome, nunca se aplica sola, y se omite cuando nada se parece lo suficiente. Luego vienen las categorías del tipo correspondiente (ingresos para el dinero que entra, gastos para el que sale), las más usadas primero. Escribe para filtrar, o escribe un nombre nuevo completo como `Expenses:Gifts` para crearla. Las transferencias y las transacciones divididas se muestran pero no se pueden recategorizar ahí.

**Hacer copias de seguridad.** Pulsa `S` para abrir la ventana de copias de seguridad. Muestra la base de datos, cuándo se hizo la última copia ("2026-10-22 14:00 · hace 3 días") y cuántas hay en la carpeta de copias, que está junto a la base de datos (`backups/`). `enter` escribe una instantánea con el nombre de archivo de la línea *Guardar en*, que empieza siendo `thaler-<fecha>-<hora>.db` en esa carpeta. Puedes escribir cualquier otra ruta en su lugar (`~` es tu carpeta personal), o solo una carpeta, que recibe dentro el nombre con la fecha y la hora. Un archivo que ya existe nunca se sobrescribe. Después de escribirla, Thaler abre la instantánea y ejecuta sobre ella la comprobación de integridad de SQLite; una instantánea que falla se elimina y se informa, así que una copia que se anuncia es una copia que se abre.

**Un recordatorio para hacer copias.** Cuando la copia más reciente de la carpeta de copias tiene 7 días o más, o no hay ninguna y tienes transacciones, la barra inferior empieza con "Última copia de seguridad hace 9 días: S crea una nueva" (o "Todavía no hay copias de seguridad") hasta que hagas una. Pon `backup_reminder_days = 14` en `config.toml` para otro intervalo, o `0` para desactivar el recordatorio. Solo cuentan las copias de la carpeta de copias, como en la ventana; las que escribiste en otro sitio y las copias de `replaced/` y `pre-migration/` no. Se comprueba al arrancar Thaler, después de una copia, después de editar la configuración y (como mucho una vez por minuto) al pulsar una tecla, así que una copia hecha por un script con Thaler abierto también termina el recordatorio.

**Eliminar copias antiguas.** Las copias se acumulan, y nada elimina una por sí solo. Thaler conserva las 10 más recientes en cada una de tres carpetas: las copias que haces (`backups/`), las bases de datos que reemplazaron las restauraciones (`backups/replaced/`) y las copias hechas antes de las actualizaciones (`backups/pre-migration/`). Cuando una carpeta tiene más, la barra inferior dice "Se pueden eliminar 3 copias de seguridad antiguas: ctrl+p". `ctrl+p` lista exactamente qué archivos se irían, los más antiguos, con sus fechas y tamaños, y `enter` los elimina; `esc` los deja. "Antiguo" es la hora en que un archivo se modificó por última vez, las copias normales y las cifradas cuentan juntas, y las más recientes siempre se quedan. Solo se listan archivos con nombre de copia (`thaler-*.db`, `thaler-*.db.age`), así que nada más de esas carpetas, ni las copias que escribiste en otro sitio, se toca nunca. Pon `keep_backups = 20` en `config.toml` para otro número, o `0` para conservarlo todo y dejar de ofrecerlo. Desde un script, `thaler cli prune` lista lo que se iría y `thaler cli prune --yes` lo elimina. Eliminar es definitivo; una copia eliminada no está en la papelera.

**Cifrar una copia.** Por defecto una copia es un archivo SQLite normal, que cualquiera que lo consiga puede leer. Pulsa `tab` hasta la línea *Contraseña* y escribe una (se muestra como `•`), luego `tab` hasta *Repetir* y escríbela otra vez, para que una errata no te deje fuera. La copia se escribe entonces como un archivo [age](https://age-encryption.org) terminado en `.age`, sellado con una clave derivada de la contraseña mediante scrypt (tarda un segundo o dos, a propósito; la ventana muestra un indicador de actividad y lo que está haciendo, e ignora las teclas hasta terminar, salvo `ctrl+c`, que sale justo después). Thaler descifra el resultado una vez antes de decir que ha terminado, para asegurarse de que la contraseña que tiene lo abre. La copia sin cifrar existe solo un momento, en una carpeta privada junto a la copia, y se borra. **No hay forma de recuperar una copia cuya contraseña se ha perdido.** La ventana y la línea de estado dicen si una copia está cifrada, y la línea *Última* lo dice de la más reciente.

**Una copia antes de cada actualización.** Cuando una versión nueva de Thaler tiene que cambiar la estructura de una base de datos que ya tiene datos, primero escribe una copia comprobada en `backups/pre-migration/` junto a la base de datos, llamada `thaler-<hora>-before-<migración>.db`, y dice dónde está por la salida de error estándar. Si la copia no se puede hacer, la actualización no ocurre y no cambia nada. Una base de datos nueva, una que ya está al día y una escrita por una versión más nueva (que se rechaza) no reciben copia. Estas copias no están cifradas y se guardan aparte de las que haces tú para que nunca cuenten como tu "última copia"; `ctrl+p` y `thaler cli prune` las eliminan (véase más arriba).

**Restaurar.** `thaler cli restore FILE` sustituye la base de datos por una copia, normal o cifrada (pide la contraseña, o lee `--passphrase-file`). La copia se lee primero en un archivo nuevo y se comprueba: una que está dañada, no es una base de datos de Thaler o la hizo una versión más nueva se rechaza sin cambiar nada. Solo entonces la base de datos actual se mueve, nunca se borra, a `backups/replaced/` junto a ella, y la copia ocupa su lugar. Ejecutar `thaler cli restore` sobre el archivo de `backups/replaced/` deshace una restauración (el comando lo muestra). Funciona cuando la base de datos actual está dañada o falta. Una copia de una versión anterior se actualiza, tras hacer una copia de ella, la próxima vez que arranque Thaler. Cierra antes cualquier otro Thaler; la restauración no busca ninguno.

**Restaurar desde la interfaz.** `ctrl+r` abre la ventana de restauración. Lista las copias de la carpeta de copias, la más nueva primero, y después las bases de datos que reemplazaron restauraciones anteriores (marcadas "reemplazada por restauración"), así que una restauración se puede deshacer desde el mismo sitio. Elige una con `↑`/`↓`; para una copia cifrada, `tab` hasta *Contraseña* y escríbela. `enter` pregunta una vez más, nombrando el archivo y dónde se guardará tu base de datos actual, y un segundo `enter` (o `y`) restaura. No pasa nada hasta entonces, y una copia dañada, con la contraseña equivocada o que no es una base de datos de Thaler se rechaza con la base de datos intacta y la ventana todavía abierta. Tras una restauración la pantalla muestra los datos restaurados y el deshacer empieza de nuevo (no puede ir más allá de ella). Una copia que no está en la carpeta: `thaler cli restore FILE`.

Para volver a abrir una copia cifrada, `thaler cli decrypt FILE.age [DEST]` pide la contraseña y escribe una base de datos normal (por defecto, el nombre del archivo sin `.age`; un archivo existente nunca se sobrescribe, y una contraseña equivocada no deja nada). Usa el resultado con `thaler --db DEST`. Como es un archivo age estándar, la herramienta `age` también lo abre (`age -d`).

En terminales de menos de 76 columnas se oculta el panel de detalle, y por debajo de 14 filas solo se muestra el panel enfocado.

## Varias monedas

- Cada cuenta tiene una moneda (Activos/Pasivos) o acepta cualquiera (Ingresos/Gastos/Patrimonio). Los importes nunca se convierten al guardarse.
- La **moneda base** solo afecta a los informes: `thaler cli currency` la muestra y `thaler cli currency set USD` la cambia.
- Los **tipos de cambio** los registras tú: `thaler cli rate set USD EUR 0.92` significa 1 USD = 0.92 EUR. Basta con un sentido; el inverso se deduce, y USD → MXN pasa por cualquier moneda que tenga tipos con las dos (EUR, por ejemplo). Los informes usan el tipo más reciente en la fecha del informe o antes.
- **Los presupuestos cuentan cada día a su propio tipo.** El gasto y los ingresos en otra moneda se convierten a la moneda base al tipo más reciente en el día en que se apuntaron o antes, así que introducir un tipo nuevo más tarde no mueve un mes ya contado; un día anterior al primer tipo de su moneda toma el tipo del final del mes. Un objetivo está en la moneda base, así que la pantalla de Presupuesto y `thaler cli budget` lo comparan con el gasto en cualquier moneda, y una moneda sin ningún tipo se nombra y se deja fuera.
- `thaler cli balance` muestra cada cuenta en su propia moneda más un patrimonio neto en la moneda base. Las monedas sin un tipo utilizable se nombran en un aviso y se dejan fuera del total en lugar de adivinarse.
- Mover dinero entre monedas: `thaler cli transfer --from Assets:Sparkasse --to Assets:Cash-USD --amount 100 --to-amount 108.50`. Se apunta a través de `Equity:Conversions` para que cada moneda cuadre por sí sola, y se muestra el tipo efectivo.

```sh
./thaler cli account add Assets:Cash-USD --currency USD
./thaler cli account add Assets:Cash-MXN --currency MXN
./thaler cli rate set USD EUR 0.92
./thaler cli rate set MXN EUR 0.05
./thaler cli currency set USD
./thaler cli balance
```

## Comandos

Sin argumentos, `thaler` abre la interfaz del terminal (véase más arriba). Todo lo demás está bajo `thaler cli`; ejecuta `thaler cli --help` para ver la lista. La interfaz necesita un terminal, así que los scripts y las tareas de cron usan siempre `thaler cli`, que está en inglés.

| Comando | Para qué sirve |
| --- | --- |
| `thaler cli account add NAME -c EUR` / `thaler cli account list` | el plan de cuentas; el primer segmento es el tipo (`Assets:`, `Liabilities:`, `Income:`, `Expenses:`, `Equity:`) |
| `thaler cli account rename OLD NEW` | dar un nombre nuevo a una cuenta de activo o de pasivo; sus transacciones, programaciones y mínimo se quedan con ella |
| `thaler cli account close ACCOUNT` / `thaler cli account reopen ACCOUNT` | apartar una cuenta vacía conservando su historial, o recuperarla (véase más arriba) |
| `thaler cli account balance ACCOUNT AMOUNT [--as-of DATE]` | hacer que la cuenta tenga lo que muestra tu banco, mediante un saldo inicial |
| `thaler cli add -a ACCOUNT --amount=-12.50 -t CATEGORY -p PAYEE -d DATE` | un ingreso o un gasto |
| `thaler cli split ID --line CATEGORY[=AMOUNT]... [--amount N] [--date D] [--payee P] [--memo T]` | dividir una transacción entre categorías, o cambiar cómo está dividida: las líneas dadas sustituyen a todas, una puede omitir su parte para llevarse el resto, y tienen que sumar el importe o no cambia nada; una sola línea la vuelve una transacción normal |
| `thaler cli transfer --from A --to B --amount N [--to-amount M]` | entre tus propias cuentas, también entre monedas |
| `thaler cli transfer edit ID [--from A] [--to B] [--amount N] [--to-amount M] [--date D] [--in-date D] [--memo T]` / `transfer delete ID [--yes]` | cambiar o borrar las dos mitades de una transferencia a la vez, dado el número de cualquiera de ellas |
| `thaler cli transfer link A B` / `transfer unlink ID` | hacer de dos transacciones guardadas las mitades de una transferencia, o volver a hacerlas dos normales (sin categoría) |
| `thaler cli import FILE -a ACCOUNT [--profile P] [--dry-run]` | importar un extracto del banco: CSV, OFX o QIF; el perfil se encuentra a partir del archivo (`auto`, por defecto) salvo que `--profile` nombre uno (`sparkasse`, `ofx`, `qif` o uno tuyo) |
| `thaler cli list [-a ACCOUNT] [--from D] [--to D] [-n 30]` | transacciones, las más nuevas al final |
| `thaler cli export [DEST] [-a ACCOUNT] [--from D] [--to D]` | las transacciones como CSV para una hoja de cálculo, de la más antigua a la más nueva, una línea por asiento (id, fecha, destinatario, descripción, cuenta, importe, moneda; nombres de columna en inglés, importes como decimales con punto); a la salida estándar, o a un archivo nuevo legible solo por ti que nunca se sobrescribe |
| `thaler cli recategorize [--dry-run]` | aplicar las reglas de config.toml a las transacciones que siguen sin categoría |
| `thaler cli category set ID CATEGORY` | pasar una transacción a otra categoría (que se crea si es nueva) |
| `thaler cli balance [--as-of D] [--all]` | saldos y patrimonio neto |
| `thaler cli budget [-m YYYY-MM]` / `thaler cli budget set CATEGORY AMOUNT [-m M]` / `thaler cli budget clear CATEGORY [-m M]` | el gasto de un mes frente a sus objetivos (gastado, objetivo, arrastrado, restante), una segunda tabla con los grupos de categorías sumados (véase Grupos de categorías) y, cuando hay ingresos previstos, los ingresos frente a su plan y lo que queda sin asignar; fijar o quitar el objetivo de una categoría (el de una categoría de ingresos es el ingreso previsto); el mes por defecto es el actual y los importes están en la moneda base |
| `thaler cli report spending [--months]` / `cashflow` / `payees [--limit N]` / `networth`, cada uno con `[--from YYYY-MM] [--to YYYY-MM]` | los informes de la pantalla de Informes como tablas, para los 12 meses hasta este o los meses dados (como mucho 120): el gasto por categoría con su total y su media mensual (`--months`: una columna por mes), lo que entró frente a lo que salió con la parte ahorrada, los destinatarios que más se llevaron con su parte (se listan 20, el resto en una línea; `--limit 0` los lista todos) y el patrimonio neto al final de cada mes con el cambio; los importes están en la moneda base, cada uno al tipo de su día, y una moneda sin tipo se nombra en un aviso |
| `thaler cli forecast [--until D]` | el saldo de cada cuenta hoy y después de cada día en que una programación lo mueve |
| `thaler cli account minimum [ACCOUNT [AMOUNT] \| --amount N \| --clear]` | lo más bajo que debería llegar una cuenta de activo; `forecast` avisa del día en que llegaría |
| `thaler cli schedule` / `add NAME --unit U -a A --amount N [--to ACCOUNT] [--tolerance P] [--end D]` / `edit ID` / `delete ID` / `pause ID` / `resume ID` / `due [--until D]` / `confirm ID DATE [--amount N] [--to-amount N]` / `skip ID DATE` | transacciones recurrentes: definirlas, listar las fechas que vencen y confirmar (opcionalmente por otro importe) o saltar cada una; no se apunta nada sin una confirmación |
| `thaler cli currency [set CODE]`, `thaler cli rate set/list` | moneda base y tipos de cambio |
| `thaler cli backup [DEST] [--encrypt \| --passphrase-file F]` | instantánea coherente mediante `VACUUM INTO`, comprobada después de escribirse; **sin cifrar** salvo que se dé `--encrypt` (pide una contraseña dos veces) o `--passphrase-file` (la primera línea de un archivo, para scripts), que escriben un archivo age terminado en `.age`; también `S` en la interfaz |
| `thaler cli decrypt SRC [DEST] [--passphrase-file F]` | abrir una copia cifrada como archivo de base de datos normal, y comprobarlo |
| `thaler cli prune [--keep N] [--yes]` | listar las copias más allá de las N más recientes de cada carpeta de copias (por defecto 10, o `keep_backups`); con `--yes`, eliminarlas |
| `thaler cli restore SRC [--passphrase-file F]` | sustituir la base de datos por una copia (normal o cifrada), conservando la que reemplaza en `backups/replaced/`; también `ctrl+r` en la interfaz |
| `thaler cli check` | comprueba que cada transacción cuadra por moneda y que la base de datos está intacta |

Escribe los importes negativos como `--amount=-12.50`. Los importes admiten `12.50`, `12,50` y `1.234,56`; una entrada ambigua como `1,234` se rechaza en lugar de adivinarse.

**Para scripts: `--json`.** Cada listado (`account list`, `account minimum`, `list`, `balance`, `budget`, `rate list`, `schedule list`, `schedule due`, `forecast`, `prune` y los cuatro `report`) admite `--json`, que muestra un único documento JSON en lugar de la tabla y nada más (lo que una tabla dice en un aviso, como una moneda sin tipo de cambio, está en los datos como una lista `missing`; `prune --json` solo lista, y rechaza `--yes`). El documento es lo que respondió el servicio, escrito igual en todas partes: los objetos tienen claves en `snake_case` en un orden fijo (`spent_total`, `schedule_id`), las listas son `[]` cuando están vacías y nunca `null`, un importe es `{"amount": "-12.50", "currency": "EUR"}` con el importe como texto con punto (nunca un número, para que no se pierda ninguna cifra), los días son `YYYY-MM-DD`, los meses `YYYY-MM`, los instantes RFC 3339 en UTC, y un tipo de cambio es su decimal exacto como texto. `thaler cli export` escribe las transacciones como CSV.

## Hoja de ruta

[ROADMAP.md](ROADMAP.md) (en inglés) lista lo que está hecho y lo previsto, como hitos, épicas e historias con identificadores permanentes. En resumen: primero una interfaz de terminal completa que funcione bien en local, en inglés, español y alemán (`M-TUI`: presupuestos con arrastre, informes, transacciones recurrentes y una previsión, restauración, y versiones con un calendario regular), después un servidor que se puede alojar uno mismo y cuyo único punto de entrada, la app-gateway, expone la API, para que un hogar pequeño (hasta unas cuatro personas) pueda compartir un Thaler, con cuentas privadas que los demás no ven (`M-SERVER`), luego una aplicación web en Next.js probada con Vitest (`M-WEB`), y por último una aplicación web móvil instalable que funciona sin conexión (`M-PWA`).
