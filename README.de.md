# thaler

[English](README.md) · [Español](README.es.md) · Deutsch

Ein Planer für die privaten Finanzen, der lokal arbeitet. Eine Go-Binärdatei, eine SQLite-Datei, kein Server, keine Verbindung zur Bank.

- Doppelte Buchführung (Konten, Transaktionen, Buchungszeilen), Beträge als ganze Zahlen der kleinsten Einheit jeder Währung gespeichert
- Mehrere Währungen: Basiswährung standardmäßig EUR, umstellbar auf USD, MXN oder jeden anderen Code
- Idempotenter Import von Bankexporten mit Kategorisierung durch Regeln: CSV (eingebaut für die **Hamburger Sparkasse**, eigene Profile für andere Banken), OFX und QIF
- `thaler` startet die interaktive Terminaloberfläche (Fenster im Stil von lazygit); jede Aktion gibt es auch als Unterbefehl `thaler cli …`, sie lässt sich also skripten (cron, Shell)

> **Stand: früh, für eine Person.** Es funktioniert lokal und hat Tests, und das Importprofil der Sparkasse wurde an einem
> echten Bankexport ausprobiert, aber es gibt keinen Mehrbenutzerbetrieb und keinen Server (siehe die [Roadmap](#roadmap)).

## Installation

Thaler läuft im Terminal unter **macOS und Linux**, Intel und ARM. Es ist eine einzige Datei und braucht weder einen C-Compiler noch andere Bibliotheken. Windows wird nicht unterstützt; die später geplante Webanwendung läuft in jedem Browser. Lade entweder ein Release herunter oder baue es aus dem Quellcode, wofür du **Go 1.27 oder neuer** brauchst. Ein Homebrew-Paket ist geplant (`PLT-7` in der [Roadmap](ROADMAP.md)).

**Ein Release.** Jedes Release auf der [Release-Seite](https://github.com/melancholypurin/thaler/releases) hat ein Archiv pro System (`thaler_<Version>_darwin_arm64.tar.gz` für einen Mac mit Apple-Chip, `darwin_amd64` für einen Intel-Mac, `linux_amd64` und `linux_arm64`) und `checksums.txt` mit seiner Signatur, `checksums.txt.sigstore.json`. Prüfe, dass die Prüfsummen vom Release-Workflow dieses Repositorys signiert wurden, prüfe das heruntergeladene Archiv gegen sie, entpacke es und lege `thaler` in deinen `PATH`:

```sh
cosign verify-blob --bundle checksums.txt.sigstore.json \
  --certificate-identity-regexp '^https://github\.com/MelancholyPurin/thaler/\.github/workflows/release\.yml@refs/heads/(main|release/[0-9]+\.[0-9]+)$' \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com checksums.txt
grep thaler_0.3.0_linux_amd64.tar.gz checksums.txt | sha256sum -c      # unter macOS: shasum -a 256 -c
tar -xzf thaler_0.3.0_linux_amd64.tar.gz
mkdir -p ~/.local/bin && mv thaler ~/.local/bin/                        # ~/.local/bin muss im PATH sein
thaler --version
```

Der erste Befehl braucht [cosign](https://docs.sigstore.dev/cosign/system_config/installation/) (`brew install cosign`). Er gibt `Verified OK` aus, wenn die Prüfsummen vom Release-Workflow von `MelancholyPurin/thaler` signiert wurden, gestartet von `main` oder einem Release-Branch: Die Signatur kommt ohne Schlüssel aus, sie entsteht über [Sigstore](https://www.sigstore.dev) mit der Identität, die GitHub diesem Workflow gibt, und steht im öffentlichen Log von Sigstore, es gibt also keinen Schlüssel, dem man vertrauen oder den man verlieren könnte. Releases sind ab `v0.3.0` signiert; `v0.1.0` und `v0.2.0` haben nur die Prüfsummen. Die Binärdateien selbst sind nicht von Apple signiert oder notarisiert. Lädst du eine auf dem Mac im Browser herunter, weigert sich macOS beim ersten Mal, sie zu öffnen; `xattr -d com.apple.quarantine thaler` behebt das (ein Download mit `curl` wird gar nicht markiert).

**Aus dem Quellcode.** Dieselben Schritte für Go und Thaler, in zwei Teilen:

**1. Go besorgen.** Unter macOS `brew install go`. Unter Linux folge [go.dev/doc/install](https://go.dev/doc/install): das Paket der Distribution ist oft älter als 1.27. `go version` sagt, welche du hast.

**2. Thaler installieren.** Direkt von GitHub:

```sh
go install github.com/melancholypurin/thaler/cmd/thaler@latest
```

oder aus einem Klon, der `./thaler` hinterlässt und ihm seine Version aus git gibt:

```sh
git clone https://github.com/melancholypurin/thaler
cd thaler
make build
```

`go install` legt `thaler` in `$(go env GOPATH)/bin` ab (`~/go/bin`, falls du das nicht geändert hast). Sagt die Shell danach `thaler: command not found`, füge diesen Ordner in `~/.zshrc` (macOS) oder `~/.bashrc` (Linux) zum `PATH` hinzu und öffne ein neues Terminal:

```sh
export PATH="$PATH:$(go env GOPATH)/bin"
```

**3. Prüfen.** `thaler --version` zeigt die Version, und `thaler` öffnet die Oberfläche. Datenbank und Konfiguration liegen auf beiden Systemen in denselben Ordnern (siehe unten).

## Schnellstart

```sh
thaler cli account add Assets:Sparkasse --currency EUR
thaler cli import --account Assets:Sparkasse --dry-run export.csv   # Vorschau, schreibt nichts
thaler cli import --account Assets:Sparkasse export.csv
thaler cli balance
thaler cli budget set Expenses:Groceries 400   # ein Monatsziel
thaler cli budget                              # dieser Monat gegen seine Ziele
thaler cli list -a Expenses:Uncategorized

thaler                         # ohne Argumente: die interaktive Oberfläche
thaler --version               # welcher Build das ist
```

`thaler --version` zeigt die Version, mit der die Binärdatei gebaut wurde. `make build` setzt sie aus git (das nächste Tag, sonst der Commit, mit `-dirty`, wenn Dateien geändert sind); ein einfaches `go build` oder `go install` nimmt die Version, die Go festgehalten hat, und `dev`, wenn es keine festgehalten hat. Aus einem Klon rufst du die Befehle als `./thaler` auf.

Exportiere deine Umsätze im Online-Banking der Sparkasse als CSV und wähle dabei das Format **CSV-CAMT** (die Variante CSV-MT940 verwendet dieselben Spaltennamen, die thaler liest).

**OFX und QIF.** Eine Bank, die einen OFX-Auszug (auch QFX genannt, nach Quicken) oder eine QIF-Datei anbietet, braucht kein Profil: Die eingebauten Profile `ofx` und `qif` lesen sie, und `auto` erkennt sie an ihren ersten Zeilen. Aus einem OFX-Auszug wird jede Transaktion eine Zeile mit ihrem Buchungstag, ihrem Betrag in der Währung, die der Auszug nennt, dem Namen der Gegenseite, dem Vermerk und der Art der Transaktion (`POS`, `DEBIT`, die die Regeln wie einen Buchungstext sehen); die Versionen 1 und 2 funktionieren beide, und eine Datei mit den Auszügen mehrerer Konten wird abgelehnt, weil ein Import in ein Konto geht. Eine QIF-Datei eines Bank-, Bargeld- oder Kreditkartenkontos liefert Datum, Betrag, Empfänger, Vermerk und Nummer (`N`), in der Währung des Kontos; die Kategorie, die sie vielleicht nennt, überlässt Thaler deinen Regeln, und eine Datei eines Depotkontos wird abgelehnt. Ein QIF-Datum hat keine feste Reihenfolge, deshalb wird die erste Reihenfolge verwendet, die *jedes* Datum der Datei lesen kann, die europäischen vor Quickens amerikanischer `10/4'26`: Eine Datei, deren Tage alle 12 oder kleiner sind, könnte beides sein; schreibt deine Bank also `DD/MM/YY`, lege ein Profil mit `format = "qif"` und seinen `date_formats` an (siehe `config.example.toml`), das `auto` dann bevorzugt.

**Wie eine Datei gelesen wird.** Das Zeichen zwischen den Spalten und die Kodierung werden aus der Datei ermittelt, nicht angenommen. Das Trennzeichen ist dasjenige von `;`, `,`, Tabulator und `|`, das die Kopfzeile in die Spalten teilt, die das Profil braucht (tut das keines, das, das sie am stärksten teilt, damit der Fehler die Kopfzeile lesbar zeigt). Die Kodierung ist UTF-8, UTF-16 (mit Byte-Order-Mark oder an seinen Null-Bytes erkannt; was eine Tabellenkalkulation als „Unicode-Text“ speichert) oder, für alles andere, Windows-1252, das deutsche Banken noch verwenden. Ein Export, den eine Tabellenkalkulation geöffnet und mit Kommas oder als UTF-16 mit Tabulatoren wieder gespeichert hat, wird also weiterhin mit dem Profil `sparkasse` importiert und von `auto` erkannt. `thaler cli import --dry-run` sagt, wie die Datei gelesen wurde. Ein eigenes Profil kann beides festlegen: `delimiter = ";"`, `encoding = "utf-8"` (oder `"utf-16"`, `"utf-16le"`, `"utf-16be"`, `"windows-1252"`); beide stehen standardmäßig auf `"auto"`.

Die Daten liegen in `~/.local/share/thaler/thaler.db`, nur für dich lesbar, wo auch immer sie liegen (Thaler macht die Datei beim Öffnen privat), die Konfiguration in `~/.config/thaler/config.toml`. Ändern lässt sich das mit `--db` / `--config` oder mit `THALER_DB`, `XDG_DATA_HOME`, `XDG_CONFIG_HOME`.

## Kategorisieren: `config.toml`

Jeder Schlüssel, mit dem, was er annimmt, und seinem Standardwert, steht in [docs/config.de.md](docs/config.de.md).

Drücke in der Oberfläche auf jedem Bildschirm `C`, um die Konfiguration in deinem Editor zu öffnen (`$VISUAL`, sonst `$EDITOR`, sonst `nano` oder `vi`; bei einem grafischen Editor dessen Warte-Option verwenden, z. B. `EDITOR="code --wait"`). Gibt es noch keine Datei, wird sie aus `config.example.toml` angelegt, mit allen Beispielen ausgeschaltet. Wenn der Editor schließt, liest Thaler die Datei neu und sagt dir, ob sie einen Fehler hat. Ohne die Oberfläche kopierst du `config.example.toml` selbst nach `~/.config/thaler/config.toml`. Regeln fügst du so hinzu:

```toml
[[rule]]
contains = "REWE"
category = "Expenses:Groceries"
```

Die erste passende Regel gewinnt. Was zu keiner passt, landet in `Expenses:Uncategorized` / `Income:Uncategorized`. Regeln greifen beim Import und noch einmal auf Wunsch: Nachdem du deine Regeln geändert hast, zeigt `thaler cli recategorize --dry-run` eine Vorschau, und `thaler cli recategorize` wendet sie auf alles an, was noch keine Kategorie hat. Transaktionen, die du selbst kategorisiert hast, werden nie angefasst.

**Sprache.** Thaler spricht Englisch, Spanisch (`es`) und Deutsch (`de`). `language = "de"` in `config.toml` wählt sie (in der Oberfläche öffnet `ctrl+l` eine Liste der Sprachen: Der Bildschirm wechselt sofort, ohne Neustart, und Thaler schreibt `language = "…"` für dich in `config.toml`, ändert dabei nur diese Zeile und lässt deine Kommentare und Regeln, wie sie sind; lässt sich die Datei nicht schreiben, wechselt die Sprache trotzdem bis zum Beenden, und die Statuszeile sagt es); ohne den Schlüssel entscheidet die Umgebung (`LC_ALL`, `LC_MESSAGES`, dann `LANG`, wie in `de_DE.UTF-8`), und eine Sprache, die Thaler nicht spricht, ist Englisch. In der Oberfläche werden Beträge und Daten so geschrieben, wie die Sprache sie schreibt: `1,234.56` auf Englisch, `1.234,56` auf Deutsch und Spanisch, und Daten als `2026-10-01` auf Englisch (ISO, das sich weder als Monat zuerst noch als Tag zuerst lesen lässt), `01.10.2026` auf Deutsch und `01/10/2026` auf Spanisch. Ein Datum, das du eintippst, wird in diesem Format gelesen und außerdem in ISO und `DD.MM.YYYY`, `01/10/2026` wird also auf Spanisch verstanden und auf Englisch als mehrdeutig abgelehnt; ein Betrag wird wie bisher auf beide Arten gelesen (`12.50` oder `12,50`), und ein Wert wie `1,234` wird als mehrdeutig abgelehnt. `thaler cli` ist Englisch, egal welche Sprache eingestellt ist, und gibt Beträge und Daten in der schlichten Form aus (`1234.56`, `2026-10-01`), damit sich Skripte nicht mit der Sprache des Rechners ändern; es liest `YYYY-MM-DD` und `DD.MM.YYYY` und lehnt ein Datum mit Schrägstrichen als mehrdeutig ab. Jeder Bildschirm und jedes Fenster passt in allen drei Sprachen in ein Terminal mit 80 Spalten und 24 Zeilen, und ein Test zeichnet in jeder Sprache etwa siebzig davon, um es zu belegen: Ein langer Text bricht in die nächste Zeile um, die untere Leiste lässt die am wenigsten nützlichen Tastenhinweise weg, wenn die Zeile voll ist (`?` listet immer alle), ein langer Status verliert seine letzten Teile, und die Hilfe von `?` scrollt mit `↑`/`↓`, wenn sie höher ist als der Bildschirm. Auch Mengenangaben folgen der Sprache (`1 Backup`, `2 Backups`). Die Namen, die Thaler Konten selbst gibt, erscheinen in der Oberfläche in der Sprache, in der du sie liest: die Typen (`Assets:Bank` ist auf Deutsch `Vermögen:Bank` und auf Spanisch `Activos:Bank`) und die Konten, die es anlegt (`Expenses:Uncategorized` ist `Ausgaben:Ohne Kategorie`); die Namen, die du gewählt hast, bleiben, wie sie sind. Gespeichert werden sie auf Englisch, und so tippst du sie, so gibt `thaler cli` sie aus und so nennt sie eine Regel in `config.toml`; an deinen Daten und Skripten ändert sich also nichts, wenn die Sprache wechselt. Fehler werden im selben Katalog nachgeschlagen, über den festen Code, den der Dienst ihnen gibt (`account_not_found`, `transfer_same_account`, …), sie folgen also in der Oberfläche der Sprache (die Befehlszeile zeigt sie auf Englisch), ob sie aus dem Geldbuch, dem Dienst, dem Importer oder der Konfigurationsdatei kommen (ein Fehler, der einen anderen umschließt, etwa eine Datei, die sich nicht lesen lässt, wird übersetzt und zeigt danach die Worte des Systems selbst). Alles, was `thaler cli` ausgibt (Hilfe, Optionen, Meldungen, Fehler), ist absichtlich nur Englisch. Der gesamte Text der Oberfläche (jede Beschriftung, jeder Hinweis, jedes Fenster, jede Statuszeile und die Hilfe von `?`) steht im Meldungskatalog und ist ins Spanische und Deutsche übersetzt; eine Meldung, die einer Sprache fehlt, erscheint auf Englisch. Das Spanische ist vollständig durchgesehen und geprüft; das Deutsche ist ebenfalls gelesen und gut genug zum Benutzen, aber seine Formulierungen können sich in einem späteren Release noch ändern. Wo die Oberfläche eine Beschriftung kürzt, sind kurze Wörter gewählt (ein Empfänger heißt auf Spanisch `Destinatario`, eine Beschreibung auf Deutsch `Notiz`).

**Farben.** Die Oberfläche verwendet vier Farben (Grün für die Auswahl und den Fokus, Orange für eine Warnung, Rot für einen Fehler, Grau für Nebensächliches) und wählt das Paar, das zum Terminal passt: Sie fragt das Terminal, ob sein Hintergrund hell oder dunkel ist. Wo das Terminal nicht antwortet (manche Multiplexer, eine Sitzung über ssh), kann sie falsch raten und blassen Text auf blassen Hintergrund zeichnen. `theme = "dark"` oder `theme = "light"` in `config.toml` behebt das, und `theme = "auto"` (der Standard) folgt dem Terminal. In der Oberfläche öffnet `ctrl+t` die Liste: Beim Durchgehen wird jedes Farbschema sofort auf dem Bildschirm ausprobiert, `enter` behält eines und schreibt `theme = "…"` in `config.toml` (nur diese Zeile, wie bei der Sprache; lässt sich die Datei nicht schreiben, wechselt das Schema trotzdem bis zum Beenden, und die Statuszeile sagt es), und `esc` stellt das bisherige wieder her. Die Musterzeile aus vier Punkten zeigt die Farben. Ein Schema ändert nur Farben: Die Auswahl ist invertiert und die übrige Hervorhebung fett, nichts hängt also allein an der Farbe, und mit der Umgebungsvariablen `NO_COLOR` zeichnet die Oberfläche ganz ohne Farben. Ein unbekanntes Schema in der Datei wird mit einer Meldung abgelehnt, die die vorhandenen aufzählt.

**Unfertige Funktionen.** Eine Story, die vor ihrer Fertigstellung eingebaut wird, bleibt ausgeschaltet, bis `config.toml` sie in einer Tabelle `[features]` einschaltet (`some_feature = true`). So hält eine unfertige Story kein Release auf. Ein Name, den es nicht gibt, wird abgelehnt, und der Fehler zählt die vorhandenen auf. In dieser Version ist nichts hinter einem Schalter.

Denselben oder einen überlappenden Export noch einmal zu importieren ist sicher: Jede Zeile erhält einen festen Hash (Konto, Datum, Betrag, Gegenseite, IBAN, Verwendungszweck, Buchungstext). Zwei wirklich gleiche Buchungen an einem Tag werden durchnummeriert und bleiben so beide erhalten. Zeilen, die die Bank als *Umsatz vorgemerkt* kennzeichnet, werden ignoriert, bis sie gebucht sind.

## Terminaloberfläche

`thaler` allein (ohne Argumente) öffnet eine Oberfläche, die wie lazygit aufgebaut ist: Fenster links und rechts ein Detailbereich, der zeigt, was gerade ausgewählt ist.

```
╭─ [1] Home ───────────────────────────────╮╭─ thaler ─────────────────────────────────────────╮
│thaler  local-first finance               ││                                                  │
╰──────────────────────────────────────────╯│             ╺┳╸ ╻ ╻ ┏━┓ ╻   ┏━╸ ┏━┓              │
╭─ [2] Accounts ───────────────────────────╮│              ┃  ┣━┫ ┣━┫ ┃   ┣╸  ┣┳┛              │
│All accounts                    -42.00 EUR││              ╹  ╹ ╹ ╹ ╹ ┗━╸ ┗━╸ ╹┗╸              │
│Bank                            -47.00 EUR││                                                  │
│Savings                           5.00 EUR││           local-first personal finance           │
╰───────────────────────────────── 1 of 3 ─╯│                                                  │
╭─ [3] Transactions ───────────────────────╮│   Net worth       -42.00 EUR                     │
│2026-10-04 » to savings              -5.00││   Accounts        2                              │
│2026-10-03 ● Kino                   -12.00││   Transactions    4                              │
│2026-10-02 ● REWE                   -20.00││   Period          2026-10-01 → 2026-10-04        │
│2026-10-01   REWE                   -10.00││   Uncategorized   2  ●  press 3, then u to review│
│                                          ││   Base currency   EUR                            │
│                                          ││                                                  │
╰───────────────────────────────── 1 of 4 ─╯╰──────────────────────────────────────────────────╯
```

(Die Aufnahme ist auf Englisch; auf Deutsch heißt es in der Oberfläche Start, Konten, Transaktionen, Nettovermögen usw.)

Die Leiste oben wechselt zwischen den **Ansichten**, und der Zeitraum rechts darin (`[ Okt 2026 ]`) gilt für alle. Sie beginnt beim aktuellen Monat.

| Ansicht | Taste | Was sie zeigt |
| --- | --- | --- |
| Geldbuch | `L` / `F1` | die drei Fenster unten: die Konten und die Transaktionen des Zeitraums |
| Budget | `B` / `F2` | Einnahmen und Ausgaben nach Kategorie für den Zeitraum, mit Anteilsbalken; links die Monate. Für einen Monat zeigen die Kategorien mit einem Ziel, was ausgegeben wurde, das Ziel und was übrig ist (rot, sobald überschritten), und `tab` wechselt in die Kategorien, wo `enter` die Transaktionen hinter der Zahl einer Kategorie zeigt; `e` setzt oder entfernt ein Ziel und schaltet den Übertrag einer Kategorie um (siehe unten) |
| Prognose | `F` / `F3` | deine Zeitpläne und wann jeder als Nächstes fällig ist, und eine Warnung für ein Konto, das unter sein Minimum fallen würde; `tab` wechselt zu den Salden jedes Kontos Woche für Woche, `a` zu einem Konto nach dem anderen |
| Berichte | `R` / `F4` | was jede Kategorie in den 12 Monaten bis zum gezeigten ausgegeben hat (bis zu diesem Monat für die ganze Zeit): eine Liste der Kategorien, jede mit einem kleinen Diagramm ihrer Monate und ihrer Summe, und für die ausgewählte ihre Monate als Balken mit Summe und Monatsdurchschnitt. `↑`/`↓` wählen die Kategorie (die erste Zeile sind alle Ausgaben), und `[` `]` `t` `T` verschieben die 12 Monate. **`tab`** wechselt zum zweiten Bericht, Einnahmen gegen Ausgaben: eine Zeile pro Monat mit dem, was hereinkam, was hinausging, was übrig blieb, und welcher Anteil der Einnahmen das ist (negativ, wenn mehr hinaus- als hereinging, ein Strich für einen Monat ohne Einnahmen), ein Balken, wie viel der Einnahmen ausgegeben wurde (voll und mit `!` am Ende, wenn es mehr war), und die Summe; `↑`/`↓` scrollen die Monate. **Noch einmal `tab`** zeigt die Empfänger: eine Zeile für jeden, der mit dem meisten zuerst, mit einem Balken gegen den größten, was er bekam, seinem Anteil an allen Ausgaben und wie viele Transaktionen das waren (Empfänger werden ohne Rücksicht auf Groß- und Kleinschreibung und Leerzeichen unterschieden, Transaktionen ohne Empfänger sind eine Zeile, eine Erstattung zählt gegen ihren Empfänger, und nach 100 Empfängern ist der Rest eine Zeile); `↑`/`↓` scrollen. **Ein drittes `tab`** zeigt das Nettovermögen: eine Zeile pro Monat mit dem Wert der Konten an seinem letzten Tag (alles bis dahin Gebuchte), der Änderung zum Vormonat und einem Balken gegen den höchsten Monat (`▒` unter null); der Saldo jedes Kontos wird zum Wechselkurs dieses Tages gezählt, ein später eingetragener Kurs verschiebt also keinen vergangenen Monat, und ein Monat vor dem ersten Kurs einer Währung nimmt den Kurs am Ende des Zeitraums; `↑`/`↓` scrollen, und ein viertes `tab` führt zurück zu den Kategorien. **`r`** wählt die Monate der Berichte: Von und Bis als `YYYY-MM` (höchstens 120 Monate; ein leeres Bis ist dieser Monat, ein leeres Von 11 Monate vor Bis, beide leer führen zurück zu den 12 Monaten bis zum gezeigten). Ein gewählter Zeitraum ist in der Überschrift markiert und bleibt, wenn `[` `]` den gezeigten Monat verschieben; ein Zeitraum von mehr als 12 Monaten wird mit einer Diagrammzelle für mehrere Monate gezeichnet, und die Balken einer Kategorie zeigen die neuesten Monate und sagen, wie viele fehlen, wobei Summe und Durchschnitt sichtbar bleiben. **`e`** speichert den gezeigten Bericht als CSV-Datei für eine Tabellenkalkulation, für die Monate, die er abdeckt: Du gibst einen Dateinamen oder einen Ordner an (vorgeschlagen wird `thaler-categories-2025-11-2026-10.csv` im Ordner, aus dem Thaler gestartet wurde), und eine Datei, die schon da ist, wird nie überschrieben. Die Datei ist absichtlich schlicht: englische Spaltennamen, Beträge in der Basiswährung als einfache Dezimalzahlen mit Punkt, Monate als `YYYY-MM`, Anteile als Prozent mit zwei Nachkommastellen; eine Zeile pro Kategorie, Monat oder Empfänger und eine Zeile `Total` für die ersten beiden (die Empfängerdatei enthält jeden Empfänger, nicht nur die ersten hundert; die Datei zum Nettovermögen ist `month,currency,net_worth`), und ein Name, den eine Tabellenkalkulation als Formel lesen würde, bekommt ein `'` davor. Was ein Bericht mangels Wechselkurs weggelassen hat, fehlt auch in der Datei, und die Statuszeile sagt es. Ein Monat mit einer Erstattung rechnet sie gegen die Ausgaben (ein Strich im Diagramm, `▒` in den Balken), und Ausgaben in einer Währung ohne Wechselkurs werden weggelassen und genannt |

**Fenster des Geldbuchs**

| Fenster | Linke Spalte | Rechter Bereich, solange es den Fokus hat |
| --- | --- | --- |
| `1` Start | eine kleine Kachel | Titelbildschirm: Nettovermögen, was von den Zielen dieses Monats übrig ist (sobald der aktuelle Monat ein Ziel oder einen Übertrag hat; rot unter null), Anzahlen, Zeitraum, Anzahl ohne Kategorie |
| `2` Konten | „Alle Konten“ und jedes Vermögens- und Verbindlichkeitskonto mit seinem Saldo | Kontoübersicht: Saldo, Aktivität, Ein- und Ausgänge dieses Monats |
| `3` Transaktionen | der Verlauf, das Neueste zuerst (`●` ohne Kategorie, `»` Umbuchung) | die ausgewählte Transaktion: Buchungszeilen, Konto, Kategorie |

Ein Konto im Fenster 2 auszuwählen, beschränkt den Transaktionsverlauf auf dieses Konto.

| Taste | Aktion |
| --- | --- |
| `L` `B` `F` `R` (oder `F1`–`F4`) | Ansicht wechseln |
| `[` `]` | voriger / nächster Monat |
| `t` / `T` | dieser Monat / ganze Zeit |

**Eine Ausgabe erfassen** geht mit wenigen Tastendrücken. Drücke `a`:

```
Betrag ⏎   Empfänger ⏎   Kategorie ⏎        z. B.   8.40 ⏎  rew ⏎  ⏎
```

- Das **Konto** ist das im Kontenfenster ausgewählte. Ist „Alle Konten“ ausgewählt, ist es das zuletzt verwendete (in dieser Sitzung oder sonst das der neuesten Transaktion in der Datenbank). Beträge sind in der Währung dieses Kontos, es gibt also keine Währung einzutippen.
- **Betrag:** `12.50` ist eine Ausgabe, `+2450` eine Einnahme.
- **Empfänger** ist der Titel der Transaktion in der Liste (später mit `r` umbenennen): Tippst du den Anfang eines bekannten Empfängers, wird er hervorgehoben, und Enter vervollständigt ihn. `↑` verwirft den Vorschlag, wenn du etwas Neues meintest.
- **Kategorie:** Zuerst wird die Kategorie angeboten, in die dieser Empfänger beim letzten Mal ging (markiert mit „gleicher Empfänger“), dann die von Empfängern, die ihm ähneln (markiert mit „ähnlicher Empfänger“), dann Kategorien der passenden Art danach, wie oft du sie benutzt. Tippe, um zu filtern, oder tippe einen vollständigen neuen Namen wie `Expenses:Gifts`. Der letzte Eintrag, „später entscheiden“, bucht sie ohne Kategorie.
- **Notiz** ist freiwillig und kommt nach dem Datum (`tab` von dort; sie ist dem schnellen Weg oben nicht im Weg). Nutze sie für einen Vermerk, wofür die Transaktion war. Sie wird neben der Transaktion gezeigt, `/` durchsucht sie, und bei einer importierten Zeile ist sie zunächst der Verwendungszweck der Bank, den du ändern oder löschen kannst.
- **Datum** ist standardmäßig heute: `y` ist gestern, `-2` vorgestern, oder tippe `2026-10-20` / `20.10.2026`. Fehler werden im Formular gemeldet, und es wird nichts geschrieben.

**Im Formular bewegen.** Die Zeile unter dem Formular sagt, was `Enter` im aktuellen Feld tut. Hinzufügen soll schnell gehen, deshalb speichert dort `Enter` in der *Kategorie*; überall sonst geht `Enter` weiter, und beim Bearbeiten läuft es durch alle Felder und speichert in der *Notiz*, sodass sich alle allein mit `Enter` erreichen lassen. Zurück geht es mit `↑` (in Betrag, Datum und Notiz wechseln `↑`/`↓` zwischen den Feldern; in den Listen für Empfänger und Kategorie geht `↑` erst durch die Vorschläge und dann zurück) oder `shift+tab`; `tab` geht vorwärts. `ctrl+s` speichert von überall, und `esc` bricht ab.

**Ein Konto anlegen** braucht keine Befehlszeile. Drücke `n`, tippe einen Namen (`Sparkasse` wird zu `Assets:Sparkasse`), wähle Vermögen oder Verbindlichkeiten und bestätige die Währung (sie beginnt als deine Basiswährung). Weißt du schon, was auf dem Konto ist, fülle **Saldo** und **Stichtag** aus; lass sie leer, um bei null zu beginnen.

**Geld zwischen deinen Konten bewegen.** Drücke `x`. Tippe den Betrag; die Konten beginnen als das ausgewählte und ein anderes mit derselben Währung, und `tab`, dann `◂ ▸` ändern sie (wählst du das Konto des anderen Feldes, tauschen die beiden). Haben die Konten unterschiedliche Währungen, erscheint ein Feld *Erhalten*: Tippe, was tatsächlich ankam, das legt den Wechselkurs fest, den du bekommen hast (`1 EUR = 1.0850 USD` erscheint beim Tippen). Eine Umbuchung wird als zwei verknüpfte Transaktionen gebucht, eine auf jedem Konto, wie die zwei Zeilen auf deinen Kontoauszügen: Sie gehen auf `Equity:Transfers` (oder `Equity:Conversions` zwischen Währungen), eine Umbuchung ist also weder Einnahme noch Ausgabe. **`e` auf einer der beiden Hälften bearbeitet die Umbuchung als Ganzes**: Dasselbe Fenster öffnet sich, mit beiden Nummern im Titel und ausgefüllt, und Betrag, Erhaltenes, Datum und die beiden Konten ändern sich auf beiden Hälften zusammen; sie behalten ihre Nummern und bleiben eine Umbuchung. Hat die Bank die beiden Hälften an verschiedenen Tagen gebucht, behält die ankommende Hälfte ihren eigenen Tag, außer du änderst das Datum (das Fenster sagt, welcher Tag das ist). Ein Empfänger, den Thaler geschrieben hat, folgt einem neuen Konto; einer von der Bank bleibt. **`d` auf einer der beiden Hälften löscht beide**, nachdem beide gezeigt wurden; markierte Transaktionen, die eine Hälfte enthalten, nehmen die andere mit. `z` nimmt eine neue Umbuchung, eine Änderung oder ein Löschen zurück, und eine gelöschte Umbuchung kommt verknüpft zurück. **Zwei vorhandene verknüpfen.** Geld, das du selbst bewegt hast, kommt oft als zwei gewöhnliche Transaktionen an, von Hand erfasst oder importiert, bevor das andere Konto es war. `l` auf einer davon listet, was ihre andere Hälfte sein könnte: Transaktionen auf einem anderen deiner Konten, die den entgegengesetzten Betrag bewegen und noch keine Umbuchung sind, die im Datum nächste zuerst; `enter` verknüpft die gewählte, und beide werden auf `Equity:Transfers` gebucht und mit `⇄` markiert, die Bewegung ist also weder Ausgabe noch Einnahme. Um zwei zu verknüpfen, die die Liste nicht anbietet (zwischen Währungen, wo die Beträge abweichen), markiere beide mit `space` und drücke `l`: Innerhalb einer Währung müssen sie denselben Betrag bewegen, einer hinaus und einer herein, und zwischen Währungen gehen sie auf `Equity:Conversions`. `l` auf einer Hälfte einer Umbuchung trennt die beiden, die dann unter Unkategorisiert warten. `z` nimmt ein Verknüpfen oder Trennen zurück. In der Befehlszeile: `thaler cli transfer link A B` und `transfer unlink ID`. `r` öffnet auf einer Hälfte weiterhin das gewöhnliche Formular, um sie umzubenennen oder ihr eine Notiz zu geben. Eine Hälfte mit `c` umzukategorisieren oder dort ihren Betrag zu ändern, löst das Paar weiterhin auf. In der Befehlszeile: `thaler cli transfer --from A --to B --amount N [--to-amount M]`. **Eine Umbuchung als Ganzes ändern oder löschen:** `thaler cli transfer edit ID` ändert beide Hälften zusammen, mit der Nummer einer der beiden: Nur die angegebenen Optionen ändern sich (`--from`, `--to`, `--amount`, `--to-amount`, `--date` für beide Hälften, `--in-date` für die ankommende, `--memo` für beide Notizen), und die Hälften behalten ihre Nummern und bleiben eine Umbuchung. Ein Empfänger, den Thaler geschrieben hat (`Transfer to Savings`), folgt einem neuen Konto; Empfänger und Text von der Bank bleiben. `thaler cli transfer delete ID` listet beide Hälften auf und löscht mit `--yes` beide, oder keine, wenn eine auf einem geschlossenen Konto liegt. Eine Hälfte allein zu löschen und mit `z` zurückzuholen, verknüpft sie wieder mit der anderen. Ein späterer Import der Kontoauszüge übernimmt die beiden Hälften (siehe unten), statt sie noch einmal hinzuzufügen.

**Konten umbenennen und schließen.** `thaler cli account rename Assets:Bank Assets:Sparkasse` gibt einem deiner eigenen Konten (Vermögen oder Verbindlichkeiten) einen neuen Namen; der neue Name behält den Typ und darf nicht vergeben sein, und alles, was zum Konto gehört (Transaktionen, Zeitpläne, sein Mindestbetrag), gehört weiter dazu, weil sich jedes davon auf das Konto bezieht und nicht auf seinen Namen. `thaler cli account close Assets:Old` legt ein Konto beiseite, wenn du es nicht mehr benutzt: Es darf nichts enthalten, in keiner Währung (bewege, was darauf ist, vorher auf ein anderes Konto), und kein Zeitplan darf darauf buchen, Schließen versteckt also nie Geld und hinterlässt keinen Zeitplan, der sich nicht bestätigen lässt; eine Ablehnung sagt, was im Weg ist. Ein geschlossenes Konto behält seinen Verlauf: Seine Transaktionen bleiben, ein Saldobericht zu einem Tag, an dem es in Gebrauch war, zählt weiter, was darauf war, und das Nettovermögen dieser Monate ändert sich nicht. Es ist in `account list` als `closed` markiert, fehlt in der Prognose und nimmt nichts Neues an: Keine Transaktion, Umbuchung, kein Import, Anfangssaldo oder Zeitplan kann darauf buchen, und seine Transaktionen lassen sich weder bearbeiten noch löschen (ihre Kategorie lässt sich noch ändern), bis `thaler cli account reopen` es zurückholt. `account list --json` gibt jedem Konto ein Feld `closed`. In der Oberfläche geht dasselbe im Kontenfenster (`2`): `r` fragt nach dem neuen Namen des ausgewählten Kontos (du tippst, was auf den Typ folgt, `Sparkasse` für `Assets:Sparkasse`; ein vergebener Name, ein anderer Typ oder kein gültiger Name wird im Fenster gesagt, und nichts ändert sich), und `c` schließt es und sagt, warum nicht, wenn Geld darauf ist oder ein Zeitplan darauf bucht. Ein geschlossenes Konto verschwindet aus dem Fenster, den Formularen und der Umbuchungsliste; `v` zeigt die geschlossenen Konten nach den anderen, abgeblendet und als `geschlossen` markiert, mit ihren Transaktionen als Verlauf, und `c` auf einem davon öffnet es wieder. Eine Transaktion eines geschlossenen Kontos lässt sich weder bearbeiten noch löschen (die Statuszeile sagt, dass du das Konto wieder öffnen sollst), aber ihre Kategorie lässt sich wie bisher mit `c` ändern. `z` nimmt ein Umbenennen, Schließen oder Wiederöffnen zurück.

**Transaktionen filtern und sortieren.** Das Geldbuch grenzt seine Liste schon nach dem im Kontenfenster (`2`) ausgewählten Konto ein, nach dem gezeigten Monat (`[` `]`, `t`, `T`), nach `u` (nur, was eine Kategorie braucht) und nach der Suche (`/`). `f` fügt mehr hinzu: einen Mindest- und einen Höchstbetrag, ein erstes und ein letztes Datum, einen Teil eines Kategorienamens und die Reihenfolge. Der Betrag ist die Größe der Transaktion auf deinem eigenen Konto, egal in welche Richtung das Geld ging (eine Ausgabe von 12.00 und eine Einnahme von 12.00 sind beide 12.00), die Grenzen zählen dazu, und in einem Geldbuch mit mehreren Währungen wird jede Transaktion in ihrer eigenen verglichen (15 heißt 15 Dollar für ein Dollarkonto und 15 Euro für ein Eurokonto). Ein Datum schreibst du so, wie die Sprache es schreibt, oder `YYYY-MM-DD`, und jede der beiden Grenzen darf fehlen: Die Daten treten im Geldbuch an die Stelle des gezeigten Monats (die Leiste oben sagt `2026-09-01 – 2026-09-30`, `ab 2026-10-04` oder `bis 2026-09-16`; die anderen Ansichten behalten den Monat). Die Kategorie wird wie bei der Suche verglichen, nach Buchstaben in Reihenfolge: `groc` findet `Expenses:Groceries`, und eine Transaktion zählt, wenn eine ihrer Kategorien passt. Die Reihenfolge wählst du im letzten Feld mit `←` `→`: Datum (das Neueste zuerst, wie bisher, oder das Älteste zuerst), Betrag (der größte oder der kleinste zuerst), Empfänger oder Kategorie, von A bis Z. Alles wirkt zusammen mit dem Konto, dem Monat, `u` und der Suche. Das Transaktionsfenster sagt `gefiltert` und `sortiert` in seinem Titel und die Statuszeile, wie viele Transaktionen passen. Ein Problem (ein Betrag, der keine Zahl ist, ein Minimum über dem Maximum, Daten in falscher Reihenfolge) wird im Fenster gesagt, und nichts ändert sich; `ctrl+x` dort hebt den Filter auf, ebenso `esc` in der Liste (die Reihenfolge bleibt, sie ist eine Vorliebe). Das Konto filterst du wie bisher, indem du es im Kontenfenster auswählst.

**Mehrere Transaktionen auf einmal.** Im Transaktionsfenster markiert `space` die unter dem Cursor (ein `✓` statt ihres üblichen Zeichens, und der Fenstertitel sagt, wie viele markiert sind) und geht nach unten, eine Reihe ist also `space space space`; `ctrl+a` markiert alles Sichtbare und lässt beim nächsten Mal alles los. `c` fragt dann nach einer Kategorie für alle markierten Transaktionen, `enter` legt sie dorthin, und `d` listet, was gleich verschwindet (die ersten paar und wie viele noch), und fragt vor dem Löschen. Beides gilt ganz oder gar nicht: Lässt sich eine davon nicht ändern (eine Umbuchung oder eine aufgeteilte Transaktion lässt sich hier nicht umkategorisieren; eine Transaktion auf einem geschlossenen Konto lässt sich nicht löschen), ändert sich keine, und die Statuszeile sagt, warum. `z` nimmt die ganze Gruppe in einem Schritt zurück, mit den Transaktionen unter ihren alten Nummern. Eine Markierung liegt nur auf einer Transaktion, die du siehst: Eine Suche, ein Filter, ein anderes Konto oder ein anderer Monat verbirgt sie, und die Markierung geht mit, was kategorisiert oder gelöscht wird, ist also immer das, was auf dem Bildschirm steht. `esc` hebt die Markierungen auf (bevor es die Suche oder den Filter löscht). Eine Regel entsteht aus einem Empfänger, deshalb hat das Kategoriefenster mehrerer Transaktionen kein Regelfeld; ist nur eine Transaktion markiert, wirken `c` und `d` auf sie, wo auch immer der Cursor steht, und das Fenster ist das übliche.

**Eine Transaktion aufteilen.** Eine Zahlung ist oft mehreres: ein Einkauf, der Lebensmittel und Haushaltswaren ist, ein Gehalt, das Lohn und Bonus ist. `s` auf einer Transaktion öffnet das Fenster zum Aufteilen (ebenso `ctrl+o` im Formular zum Anlegen oder Bearbeiten, das mitnimmt, was du getippt hast, eine neue Aufteilung beginnt also mit `a`). Es hat Konto, Betrag (mit `+` für eine Einnahme), Empfänger, Datum und Notiz wie das Formular, darunter die Zeilen, jede eine Kategorie und ihr Anteil am Betrag, ohne Vorzeichen geschrieben. Tippe ein paar Buchstaben einer Kategorie, und `↑` `↓` wählen, wie in der Kategorieliste, oder einen vollständigen neuen Namen wie `Expenses:Gifts`. Eine Zeile darf ohne Betrag bleiben und nimmt, was die anderen übrig lassen; das Fenster sagt, was noch zu verteilen ist oder um wie viel die Zeilen darüber liegen. `tab` geht durch die Felder, `ctrl+n` fügt unter der aktuellen eine Zeile hinzu, `ctrl+x` entfernt sie, `ctrl+s` speichert. Speichern wird abgelehnt, bis die Zeilen den Betrag ergeben, und vorher wird nichts geschrieben: Die Transaktion ist eine Buchung auf deinem Konto mit einer Buchungszeile pro Kategorie, jeder Bericht und das Budget zählen also den Anteil jeder Kategorie. Eine Aufteilung erscheint in der Liste als `»`; `e` oder `r` darauf öffnet dasselbe Fenster, und `z` nimmt die Änderung zurück. Eine Transaktion mit einer Zeile ist wieder eine gewöhnliche Transaktion. Nur eine Transaktion auf deinem eigenen Konto mit Einnahmen- oder Ausgabenkategorien lässt sich aufteilen: eine Umbuchung zwischen deinen Konten nicht, und die Transaktion eines geschlossenen Kontos lässt sich nicht bearbeiten. Eine Aufteilung lässt sich nicht mit `c` kategorisieren (das ist für eine Kategorie), ebenso wenig die markierten Transaktionen, die eine enthalten. Thaler selbst prüft jede Aufteilung, die es schreibt, aus dem Fenster oder aus `thaler cli split`: ein Konto von dir, Einnahmen- oder Ausgabenkategorien, die jede einen Anteil in der Währung des Kontos nehmen, und Anteile, die den Betrag ergeben.

**Den Kontostand der Bank abgleichen.** Ein Import bringt nur Bewegungen, der Saldo eines Kontos stimmt also nicht, bis Thaler weiß, wo es angefangen hat. Wähle das Konto, drücke `b` und tippe, was deine Bank an einem bestimmten Tag zeigt. Thaler bucht den Unterschied als eine Transaktion *Anfangssaldo* gegen `Equity:Opening`, datiert auf den Tag vor der ersten Transaktion des Kontos, damit der ganze Verlauf aufgeht. Drückst du nach dem nächsten Import wieder `b`, korrigiert es dieselbe Transaktion, statt eine weitere hinzuzufügen. Bei einer Kreditkarte oder einem Kredit tippe den Betrag, den du schuldest (eine Karte, die 500.00 Schulden zeigt, ist `500`). `z` nimmt die Änderung zurück. In der Befehlszeile: `thaler cli account balance ACCOUNT AMOUNT --as-of DATE`.

**Einen Bankexport importieren** geht auch aus der Oberfläche. Drücke `i`:

- **Datei:** Die Bankexporte in `~/Downloads` (CSV-, OFX- und QIF-Dateien, an ihren Endungen `.csv`, `.ofx`, `.qfx` und `.qif`) werden aufgelistet, das Neueste zuerst, der eben heruntergeladene Export ist also schon hervorgehoben. Tippe ein paar Buchstaben, um die Liste einzugrenzen, oder füge einen Dateipfad ein oder ziehe ihn ins Feld. Tippe oder ziehe einen *Ordner*pfad (etwa `~/Desktop`), um stattdessen die Exporte dieses Ordners zu listen. Soll jedes Mal ein anderer Ordner erscheinen, setze `import_dir = "~/Documents/bank-exports"` in `config.toml`.
- **Konto** (standardmäßig das im Kontenfenster ausgewählte) und **Profil** änderst du mit `tab` und `←` `→`. Das Profil beginnt mit **automatisch**: Thaler liest die Kopfzeile der hervorgehobenen (oder getippten) Datei und wählt das Profil, dessen Spalten sie hat, angezeigt als `automatisch: sparkasse` und noch einmal in der Prüfung (`Profil sparkasse`), eine Datei einer anderen Bank wird also mit deinem eigenen Profil dafür gelesen (siehe `config.example.toml`), ohne dass du etwas wählst. Ein Profil passt, wenn die Datei die Datums- und Betragsspalten hat, die es nennt; es gewinnt das, das die meisten Spalten der Datei nennt (eines, das jede Spalte eines Bankexports aufführt, schlägt eines, das zwei aufführt), und unter gleich guten kommen deine aus `config.toml`, in der geschriebenen Reihenfolge, vor den eingebauten. Passt keines, sagt `enter` das, statt zu raten, und `←` `→` wählen ein Profil von Hand, das dann so verwendet wird, wie es ist, auch wenn die Datei nicht danach aussieht, und beim nächsten Mal angeboten wird (`automatisch` bleibt `automatisch`). `thaler cli import` findet das Profil genauso, es sei denn, `--profile` nennt eines.
- `enter` zeigt eine **Prüfung** und schreibt nichts: wie viele Zeilen neu sind, wie viele schon importiert wurden, zu wie vielen keine Regel passte, und jede Zeile mit der Kategorie, die die Regeln gewählt haben. Ein zweites `enter` importiert. Lassen sich manche Zeilen nicht lesen, werden sie aufgelistet, und `y` importiert den Rest.
- **`c` ändert die Kategorie der Zeile unter dem Cursor**, bevor etwas geschrieben wird, in derselben Liste wie überall (tippe, um sie einzugrenzen, oder einen vollständigen Namen wie `Expenses:Gifts` für eine neue; `enter` wählt, `esc` lässt sie, wie sie war). Deine Wahl gewinnt gegen die Regeln und gegen die Kategorie eines Zeitplans, ist in der Prüfung mit `✎` markiert und wird vom Import geschrieben; `r` geht zurück zu dem, was die Regeln gewählt haben, und die Datei neu zu lesen vergisst jede Wahl. Die Prüfung wird jedes Mal neu berechnet, die Anzahlen folgen also: Eine Zeile, die du kategorisierst, zählt nicht mehr als ohne Kategorie, und eine Zeile, die du auf `Equity:Transfers` legst, wird wie jede Umbuchung mit der anderen Hälfte gepaart, eine, die du woanders hinlegst, nicht. `Unkategorisiert` zu wählen, lässt die Zeile für später. Eine Zeile, die schon importiert wurde oder einen deiner Einträge übernimmt, behält ihre Kategorie (die Zeile unter der Liste sagt, warum). Für eine Regel wird nichts gespeichert: Soll die Wahl beim nächsten Mal eine Regel sein, lege eine in `config.toml` an oder kategorisiere die Zeile nach dem Import mit `c`.
- Danach werden die Zeilen des Kontos ohne Kategorie gezeigt, bereit für `c`, und `z` nimmt den ganzen Import zurück.
- **Ein neuer Export fällt auf.** Solange Thaler läuft, schaut es alle paar Sekunden in den Importordner, und wenn ein Bankexport ankommt, der vorher nicht da war (der eben heruntergeladene oder einer, der unter demselben Namen neu gespeichert wurde), sagt die untere Leiste `neuer Export umsaetze.csv · i importiert ihn` oder wie viele angekommen sind. Die Datei ist schon hervorgehoben, wenn du `i` drückst, was die Meldung auch entfernt; bei offener Dateiliste kommt sie sofort in die Liste. Was beim Start von Thaler im Ordner lag oder als sich `import_dir` geändert hat, ist nicht neu, und eine Meldung erscheint nur für Dateien, deren Ankunft gesehen wurde. Gelesen werden nur Namen, Größen und Zeiten der Exporte, nie ihr Inhalt, und nichts wird importiert, bevor du es sagst. `watch_import_dir = false` in `config.toml` schaltet es aus.
- **`I` listet die gemachten Importe**, den neuesten zuerst: wann, das Konto und die Datei, und unter der Liste, was der unter dem Cursor bewirkt hat (hinzugefügte Zeilen, deine Einträge, die er übernommen hat, Umbuchungen, die er gepaart hat, Termine von Zeitplänen, die er beantwortet hat, das Profil). `enter` nimmt ihn ganz zurück, nachdem gesagt wurde, was verschwindet. Das geht mit jedem Import, nicht nur dem letzten, und auch mit einem, der mit `thaler cli import` gemacht wurde. Es löscht die Transaktionen, die der Import hinzugefügt hat, macht deine Einträge, die er übernommen hat, wieder zu Handeinträgen, setzt die anderen Hälften der gepaarten Umbuchungen auf die Kategorie zurück, die sie hatten (eine, die du seitdem geändert hast, bleibt, wie du sie gelassen hast), und macht einen Termin eines Zeitplans, den er beantwortet hat, wieder fällig. Was du an den gelöschten Transaktionen seitdem geändert hast (eine Kategorie, eine Notiz), geht mit ihnen, und `z` bringt sie nicht zurück: Dafür importiere die Datei noch einmal. Ein Import, dessen Konto geschlossen wurde, wird abgelehnt. Ein Eintrag merkt sich den Namen der Datei, nicht den Ordner, und das Profil; Importe von vor dieser Liste stehen nicht darin.

**Von Hand erfasste Einträge kommen nicht doppelt.** Erfasst du Ausgaben selbst und importierst später den Kontoauszug, wird jede Bankzeile mit dem verglichen, was du getippt hast: dasselbe Konto, genau derselbe Betrag, innerhalb von drei Tagen datiert, ein gewöhnlicher Eintrag (ein Konto, eine Kategorie), der noch keiner Bankzeile zugeordnet ist. Wird einer gefunden, *übernimmt* die Zeile diesen Eintrag. Nichts wird hinzugefügt; der Eintrag merkt sich nur, welche Bankzeile er ist, ein erneuter Import der Datei erkennt ihn also. Dein Empfänger, dein Datum und deine Kategorie bleiben, wie du sie getippt hast, egal was deine Regeln gewählt hätten. Die Prüfung zeigt solche Zeilen als `↔ #12 REWE`, bevor etwas geschrieben wird, jeder Eintrag wird höchstens einmal übernommen (das nächste Datum zuerst), und `z` löst ihn wieder. Das funktioniert auch für die beiden Hälften einer Umbuchung, die du mit `x` erfasst hast. Einträge, die Aufteilungen sind, die in einer Transaktion zwischen zwei deiner Konten bewegen oder die ein Anfangssaldo sind, werden nie zugeordnet.

**Monatsziele.** Wähle in der Budgetansicht einen Monat und drücke `e`: Ein Fenster listet deine Ausgabenkategorien mit dem Ziel, das jede in diesem Monat hat. Bewege dich mit `↑` `↓`, tippe einen Betrag, und `enter` speichert ihn; ein leerer Betrag entfernt das Ziel, und `z` nimmt eine Änderung zurück. Ein Ziel gehört zu einem Monat (jeder Monat behält sein eigenes, das Ziel des nächsten Monats zu ändern lässt diesen also in Ruhe) und ist in der Basiswährung; das Fenster setzt sie für Ausgabenkategorien (auch eine Einnahmenkategorie kann eines haben, siehe Geplantes Einkommen unten). Für diesen Monat zeigt das Budget das Gesamtziel und was davon übrig ist, und unter jeder Kategorie mit Ziel das Ausgegebene, das Ziel und was übrig ist oder um wie viel es überschritten wurde, mit Balken und Betrag in Rot. Ausgaben in Kategorien ohne Ziel werden getrennt aufgeführt und nehmen nichts von dem, was den geplanten Kategorien übrig bleibt. `c` beginnt den gezeigten Monat aus dem vorigen: Es fügt die Ziele hinzu, die dem Monat fehlen, und behält die, die er hat, nichts wird also überschrieben, und `z` nimmt genau das zurück, was es hinzugefügt hat. Die ganze Zeit hat keine Ziele: Wähle einen Monat.

**Kategoriegruppen.** Kategorien untereinander bilden eine Gruppe: `Expenses:Housing:Rent` und `Expenses:Housing:Power` gehören zu `Expenses:Housing`, ebenso tiefere wie `Expenses:Housing:Utilities:Water` (eine Gruppe ist die erste Ebene unter dem Typ; eine Kategorie, die wie die Gruppe heißt, `Expenses:Housing` selbst, zählt als eines ihrer Mitglieder, sobald es eine darunter gibt). Eine Gruppe hat nichts Eigenes einzustellen: Ihr Ziel ist die Summe der Ziele ihrer Kategorien, Ziele setzen, entfernen und kopieren funktioniert also wie bisher, und nichts wird doppelt gezählt. Der Dienst rechnet jede Gruppe für den Monat zusammen (`MonthBudget.Groups`: ausgegeben, Ziel, übertragen, übrig, und was die Kategorien ohne zurückgelegtes Geld ausgegeben haben, das wie die Zahlen des Monats selbst getrennt von dem gehalten wird, was übrig ist), und die Gruppen zusammen mit den Kategorien in keiner ergeben die Summen des Monats. `thaler cli budget` zeigt sie in einer zweiten Tabelle unter den Kategorien, und `--json` hat sie als `groups`. Die Budgetansicht zeigt sie: In einem Monat ist jede Gruppe eine Zeile, die ihre Kategorien zusammenrechnet, mit den Kategorien darunter, und `space` faltet eine Gruppe, sodass nur ihre Zeile zu sehen ist (siehe unten).

**Eine Gruppe im Budget falten.** Mit den Kategorien im Fokus (`tab`) ist eine Gruppe eine eigene Zeile, markiert mit `-`, solange ihre Kategorien darunter gezeigt werden, und mit `+`, solange sie gefaltet ist: ihr Name, was die Gruppe ausgegeben hat, ein Balken und die Summe ihrer Ziele und was übrig ist, wie bei einer Kategorie mit Ziel. Ihre Kategorien folgen eingerückt unter ihren Namen ohne den der Gruppe (`Rent` unter `Housing`), eine Kategorie ohne Ziel als eine Zeile, und die, die wie die Gruppe heißt, als `Housing (direkt)`. Eine Gruppe, die eine Kategorie mit Ziel hat, steht bei den Zielen, mit all ihren Kategorien; eine ohne steht bei den anderen ohne Ziel. `space` faltet die Gruppe, in der die Auswahl steht, oder entfaltet sie, wenn sie gefaltet ist, `←` faltet die Gruppe oder geht von einer Kategorie zu ihrer Gruppe, und `→` entfaltet sie; `↑` `↓` überspringen eine gefaltete Gruppe. `enter` auf einer Gruppe öffnet das Geldbuch mit den Transaktionen all ihrer Kategorien (der Name der Gruppe im Titel der Transaktionen), auf einer Kategorie mit ihren eigenen, wie bisher. Die ganze Zeit und die Monate ohne Ziele werden genauso gruppiert. Faltungen bleiben erhalten, solange Thaler läuft, nicht in `config.toml`.

**Die Transaktionen hinter einer Zahl.** Im Budget wechselt `tab` von den Monaten in die Kategorien (dasselbe Fenster, das die Zahlen zeigt, mit einer eigenen Markierung `▸`, scrollend, wenn mehr da sind, als passen), `↑` `↓` wählen eine, und `enter` öffnet das Geldbuch mit ihren Transaktionen: der gezeigte Monat, alle Konten und die Kategorie im Titel des Fensters. Es ist dieselbe Liste, aus der die Zahl zusammengerechnet wurde, du kannst also von dort bearbeiten, umkategorisieren oder löschen, und `esc` zeigt wieder alles. `tab` oder `esc` führt zurück zu den Monaten.

**Geplantes Einkommen.** Auch eine Einnahmenkategorie kann ein Ziel haben: was du in diesem Monat daraus zu bekommen planst. Im Zielfenster (`e`) folgen die Einnahmenkategorien auf die Ausgabenkategorien, markiert mit `+`, und das Feld heißt Geplant statt Ziel; `tab` tut dort nichts, weil Einnahmen nichts zu übertragen haben. In der Befehlszeile ist es `thaler cli budget set Income:Salary 3000 --month 2026-10`. Für einen Monat mit Plan zeigt das Budget **Geplantes Einkommen** und **Nicht zugeteilt**: das geplante Einkommen abzüglich der Ziele der Ausgabenkategorien, rot, wenn die Ziele zusammen mehr als der Plan sind. Unter den Einnahmen zeigt jede geplante Kategorie, was gegenüber dem Plan hereingekommen ist (`von 3000.00 · noch 100.00 offen` oder `400.00 mehr als geplant`); die anderen werden wie bisher aufgeführt. `c` kopiert die Pläne mit den anderen Zielen weiter. `thaler cli budget` listet sie auch: Für einen Monat mit geplantem Einkommen fügt es eine Tabelle der Einnahmen hinzu (erhalten, geplant und noch offen, negativ, sobald der Plan übertroffen ist) und eine Zeile „Unassigned: … (planned income … less targets …)“; ohne Plan ist die Ausgabe wie bisher.

**Wiederkehrende Transaktionen.** Ein Zeitplan ist eine Transaktion, die sich wiederholt: die Miete jeden Monat, ein Gehalt am 28., eine Versicherung jedes Jahr. Die Prognoseansicht (`F`) listet sie, den am frühesten fälligen zuerst, mit dem, was jeder bewegt, und wann er als Nächstes fällig ist; `↑`/`↓` gehen durch sie. Ein Termin, auf den noch niemand geantwortet hat, ist mit `!` markiert und wird über der Liste gezählt, und ein pausierter oder abgelaufener Zeitplan sagt das. **`n`** legt einen neuen an und **`e`** ändert den ausgewählten, in einem Fenster wie die anderen Formulare (`tab` und `enter` gehen weiter, `ctrl+s` speichert, `esc` bricht ab): ein Name, ein Betrag (ohne Vorzeichen geht Geld hinaus, mit `+` kommt es herein), das Konto, auf dem er sich bewegt, und wohin er geht, was du tippst und aus der Liste deiner Kategorien und anderen Konten wählst. Wählst du eines deiner Konten, wird er zur Umbuchung, die fragt, was ankommt, wenn die beiden unterschiedliche Währungen haben. Dann wie oft (alle N Wochen, Monate oder Jahre), der erste Termin, ein optionaler letzter Termin und, für alles, was keine Umbuchung ist, eine Toleranz in Prozent für Rechnungen, die schwanken. Was gebucht wird, trägt den Namen des Zeitplans. **`p`** pausiert den ausgewählten Zeitplan oder setzt ihn fort, und `z` nimmt jede dieser Aktionen zurück. Ein Zeitplan mit mehreren Buchungszeilen lässt sich nur über den Dienst ändern, nicht hier. **`enter`** geht durch das Fällige, den ältesten Termin zuerst, einen nach dem anderen (dieselben Termine wie `thaler cli schedule due`). Thaler fragt nur: `enter` bucht den Termin so, wie er ist, an seinem eigenen Tag, `e` bucht ihn mit dem Betrag, den er wirklich hatte (für eine schwankende Rechnung oder wenn anderes ankam), `s` überspringt ihn, `↑`/`↓` sehen sich einen anderen Termin an, und `esc` hört auf. Nach jeder Antwort kommt der nächste Termin, bis keiner mehr übrig ist. Eine Umbuchung wird als die zwei verknüpften Transaktionen von `x` gebucht. `z` nimmt die letzte Antwort zurück: Eine Buchung wird gelöscht und ein Überspringen aufgehoben, der Termin ist also wieder fällig. `schedule add Rent --unit month -a Assets:Bank --amount=-900 -t Expenses:Rent --start 2026-11-28` legt einen an, `--every 2` macht ihn jede zweite Woche, jeden zweiten Monat oder jedes zweite Jahr, und ein Zeitplan, der am 31. beginnt, fällt in kürzeren Monaten auf den letzten Tag. **Thaler bucht nie von selbst.** `schedule due` listet die Termine bis heute, die noch nicht beantwortet sind, und jeder wird mit `schedule confirm ID DATE` (an diesem Tag gebucht, `--amount=-950` für einen anderen Betrag) oder `schedule skip ID DATE` (nichts gebucht) beantwortet. Ein beantworteter Termin kommt nicht wieder; löschst du die Transaktion, die eine Bestätigung gebucht hat, ist ihr Termin wieder fällig. **Eine importierte Bankzeile erledigt den Termin, zu dem sie gehört:** Eine Zeile auf dem Konto des Zeitplans über genau dessen Betrag, innerhalb von drei Tagen um einen unbeantworteten Termin datiert, beantwortet diesen Termin (den nächsten, wenn zwei in Reichweite sind) und wird auf die Kategorie des Zeitplans gebucht, es sei denn, eine deiner Regeln wählt eine andere; der Import sagt es (`Settled 2026-08-28 of the schedule Rent`), `--dry-run` zählt sie mit, und den Import zurückzunehmen (`u` in der Oberfläche) macht den Termin wieder fällig. Eine Zeile, die einen deiner Handeinträge übernimmt, lässt den Zeitplan in Ruhe, überspringe diesen Termin also selbst. `schedule edit ID` ändert nur die angegebenen Optionen, `schedule delete ID` entfernt einen Zeitplan und behält, was er gebucht hat, und `schedule` allein listet sie. **Schwankende Rechnungen:** Gib für den Strom den üblichen Betrag und eine Toleranz an: `schedule add Electricity --unit month -a Assets:Bank --amount=-80 -t Expenses:Power --tolerance 25` (`edit ID --tolerance 0` macht ihn wieder genau). Eine Bankzeile innerhalb von 25 % um 80.00, darüber oder darunter, in derselben Richtung, erledigt ihren Termin trotzdem, und gebucht wird, was die Bank sagt. Listen zeigen so einen Betrag als `~-80.00 EUR`. Einen Termin von Hand zu bestätigen, nimmt `--amount` wie bei jedem Zeitplan, egal welche Toleranz. Eine geplante Umbuchung hat keine Toleranz. **Umbuchungen:** Ein Zeitplan kann Geld zwischen deinen eigenen Konten bewegen, etwa ein monatliches Sparen: `schedule add Saving --unit month -a Assets:Bank --amount 200 --to Assets:Savings` (`-a` ist das Konto, das es verlässt, `--to` das, auf dem es ankommt; zwischen Währungen sagt `--to-amount`, wie viel ankommt). Einen Termin zu bestätigen bucht eine Umbuchung, die zwei verknüpften Transaktionen von `thaler cli transfer`, und `--amount` und `--to-amount` ändern, was sich für diesen Termin bewegt. Eine Bankzeile mit demselben Betrag auf einem der beiden Konten erledigt den Termin und wird auf `Equity:Transfers` gebucht; die Zeile des anderen Kontos wird dann wie üblich mit ihr gepaart. **Beenden und pausieren:** `--end DATE` (bei `add` oder `edit`; `--end none` entfernt es) ist der letzte Tag, auf den ein Termin fallen darf. `schedule pause ID` hält ihn ab heute davon ab, etwas vorzuschlagen, und `schedule resume ID` startet ihn ab heute wieder; die Termine dazwischen entfallen, sie werden nicht aufgehoben, und eine Bankzeile erledigt keinen davon. Termine vor einer Pause, die niemand beantwortet hat, bleiben fällig. **Wohin die Salden gehen:** `thaler cli forecast [--until DATE]` rechnet aus, was jedes Konto hätte, wenn jeder Zeitplan bestätigt würde: den heutigen Saldo, dann an jedem Tag, an dem ein Zeitplan ihn bewegt, was sich ändert und den Saldo danach (90 Tage voraus, außer mit `--until`). Ein Termin, der kam und unbeantwortet blieb, zählt heute, ein übersprungener oder bestätigter nicht, ein pausierter oder beendeter Zeitplan hört auf, und eine Umbuchung bewegt beide Konten, jedes in seiner Währung. Nur die Zeitpläne zählen: Ein Kauf, den du noch nicht gemacht hast, ist nicht darin, ebenso wenig eine schon gebuchte Transaktion mit einem künftigen Datum. Nichts wird gebucht. In der Prognoseansicht wechselt **`tab`** von den Zeitplänen zu den Salden: für jedes Vermögens- und Verbindlichkeitskonto, was es heute hat, dann was es am Ende jeder der nächsten 13 Wochen hätte (die erste Woche endet in einer Woche), mit dem, was die Zeitpläne in dieser Woche bewegen; `↑`/`↓` scrollen, `tab` geht zurück. Ein Saldo unter dem Minimum des Kontos ist mit `!` markiert, und die Warnungen bleiben oben. **`a`** beschränkt die Prognose auf ein Konto, jedes Mal das nächste und nach dem letzten wieder alle, und der Titel sagt, welches: seine Zeitpläne (die, die es bewegen, eine Umbuchung auf einem seiner Konten), seine Salden und seine Warnung, und `enter` geht nur durch die Termine dieser Zeitpläne. Ein neuer Zeitplan beginnt auf diesem Konto, und einer, der für ein anderes Konto gespeichert wird, zeigt wieder alle. **Ein Minimum für ein Konto:** `thaler cli account minimum Assets:Bank 500` sagt, dass das Konto nicht unter 500.00 fallen soll (`--amount=-300` für einen vereinbarten Dispo, `--clear`, um es zu entfernen, ohne Argumente, um sie zu listen). `forecast` endet dann mit einer Warnung für jedes Konto, das darunter fallen würde, mit dem ersten Tag, dem Saldo an diesem Tag und dem Zeitplan, der am meisten davon nimmt; von einem, das schon darunter liegt, heißt es, dass es heute darunter liegt. Salden werden am Ende eines Tages verglichen, ein Gehalt und eine Miete am selben Tag werden also zusammen genommen. Vor einem Konto ohne Minimum wird nie gewarnt, und nur ein Vermögenskonto kann eines haben. In der Prognoseansicht setzt **`m`** das Minimum eines Kontos in einem Fenster (die Vermögenskonten sind mit ihrem aufgeführt; tippe einen Betrag oder lass ihn leer, um es zu entfernen; `enter` speichert, `esc` bricht ab, `z` macht rückgängig), und die Ansicht sagt über den Zeitplänen, welche Konten in den nächsten 90 Tagen unter ihres fallen würden: den ersten Tag, den Saldo an diesem Tag und den Zeitplan, der am meisten davon nimmt, oder dass das Konto schon unter seinem Minimum liegt.

**Übertrag.** Im selben Fenster lässt `tab` die Kategorie unter dem Cursor das, was von ihr übrig ist, in den nächsten Monat übertragen, ab dem gezeigten Monat (dieser Monat beginnt selbst ohne Übertrag). Was übrig war, kommt als positiver Betrag herein, und was überzogen wurde, als negativer, Überziehen wird also aus späteren Monaten zurückgezahlt. Ein Monat ohne Ziel dazwischen läuft weiter und trägt mit, was er ausgegeben hat. Gespeichert wird dafür nichts: Der Übertrag wird beim Anzeigen aus den Zielen und den Ausgaben der Monate seitdem berechnet (Ausgaben zum Wechselkurs des Tages, an dem sie gemacht wurden), eine ältere Transaktion zu bearbeiten oder zu importieren kann also nie eine veraltete Zahl hinterlassen. Das Budget zeigt für so eine Kategorie `von 50.00 · +70.00 Übertrag · 110.00 übrig` und eine Summe `Übertrag`; `z` nimmt das Umschalten zurück.

**Umbuchungen zwischen deinen eigenen Konten.** Importierst du dein Girokonto und dein Sparkonto, erscheint dieselbe Umbuchung in beiden Exporten, einmal hinausgehend und einmal hereinkommend. Als Ausgabe und als Einnahme gezählt, würde sie in der Budgetansicht beides aufblähen. Hat eine neue Zeile also genau den entgegengesetzten Betrag einer Transaktion auf einem anderen deiner Konten, innerhalb von drei Tagen, und ist noch keine von beiden kategorisiert, paart Thaler sie: Beide werden auf `Equity:Transfers` gebucht (sie sind also weder Einnahme noch Ausgabe), mit `⇄` markiert und miteinander verknüpft. Die Prüfung des Imports zeigt `⇄ Bank` auf einer gepaarten Zeile, bevor etwas geschrieben wird, und `z` nimmt die Paarung mit dem Import zurück. Es funktioniert in beiden Reihenfolgen, jede Zeile wird höchstens einmal gepaart, und eine Zeile, die eine Regel schon in eine echte Kategorie gelegt hat (etwa die Miete), bleibt in Ruhe. Lege eine Regel mit der Kategorie `Equity:Transfers` an, um eine Umbuchung zu markieren, deren andere Hälfte noch nicht importiert ist; der Saldo von `Equity:Transfers` ist das, was noch wartet. Kategorisierst du eine Hälfte um oder änderst sie, wird das Paar aufgelöst, und die andere Hälfte geht zurück zu ohne Kategorie, damit es dir auffällt.

Regeln und Profile werden bei jedem Druck auf `i` aus `config.toml` gelesen, du kannst sie also in einem anderen Fenster bearbeiten und erneut importieren.

**Kategorien umbenennen und zusammenführen.** `K` listet jede Kategorie, Ausgaben zuerst und Einnahmen mit `+` markiert, jede mit der Zahl ihrer Transaktionen; der Cursor beginnt auf der Kategorie der im Geldbuch ausgewählten Transaktion oder der im Budget ausgewählten. `r` (oder `enter`) fragt nach dem neuen Namen, vollständig geschrieben (`Expenses:Dining`) und vom selben Typ: Die Kategorie und die Kategorien darunter (`Expenses:Food:Out`) werden umbenannt, und ihre Transaktionen, Ziele, Überträge und Zeitpläne folgen; `z` nimmt es zurück. `m` fragt, in welche andere Kategorie ihrer Art sie überführt werden soll, und fragt noch einmal, bevor es alle ihre Transaktionen, Zeitpläne, Ziele (ein Monat, für den die andere schon ein Ziel hat, behält das der anderen) und den Übertrag (außer die andere hat einen) verschiebt und sie entfernt; `z` kann eine Zusammenführung nicht zurücknehmen, und eine Kategorie mit Kategorien darunter wird abgelehnt, bis diese zusammengeführt sind. Regeln in `config.toml`, die die Kategorie nennen, werden nicht geändert: Die Statuszeile sagt, wie viele es noch tun, damit du sie bearbeiten kannst (`C`).

**Die Regeln verwalten.** `M` listet die Regeln aus `config.toml` in der Reihenfolge, in der sie geprüft werden (die erste passende gewinnt), einen gesuchten Text in Anführungszeichen und einen regulären Ausdruck zwischen Schrägstrichen, jeweils mit ihrer Kategorie. `e` (oder `enter`) bearbeitet die unter dem Cursor: den Text, den sie sucht, und ihre Kategorie, wobei `tab` vom einen zum anderen geht und `enter` speichert; ein zu kurzer Text, ein Ausdruck, der sich nicht übersetzen lässt, oder eine Kategorie, die kein Name ist, wird im Fenster gesagt, und nichts wird geschrieben. `<` und `>` schieben die Regel einen Platz früher oder später, weil die Reihenfolge entscheidet, welche Regel gewinnt, und `d` löscht sie nach Rückfrage. `z` nimmt die letzte Änderung zurück, im Fenster oder nachdem es geschlossen ist, solange niemand die Datei seitdem geändert hat; Thaler schreibt nie über eine Datei, die es nicht geschrieben hat. Nur die Zeilen der Regel, die sich ändert, werden neu geschrieben: Deine Kommentare, deine Einstellungen und die anderen Regeln bleiben, wie sie sind, und ein Kommentar direkt über einer Regel (ohne Leerzeile dazwischen) wandert mit ihr; ein Kommentar auf einer der Zeilen der Regel selbst verschwindet, wenn die Regel bearbeitet wird. Eine Datei, deren Regeln nicht als `[[rule]]`-Tabellen hintereinander geschrieben sind (eine Liste, eine Zeichenkette über mehrere Zeilen), wird mit einer Meldung abgelehnt und wie bisher mit `C` bearbeitet. Die Transaktionen, die eine Regel schon kategorisiert hat, ändern sich nicht, wenn sie bearbeitet oder gelöscht wird, und eine neue Reihenfolge ändert sie auch nicht. `a` wendet die Regeln, wie sie jetzt in der Datei stehen, auf die Transaktionen an, die noch keine Kategorie haben (die, die eine Regel oder du von Hand kategorisiert hast, werden nie angefasst): Es sagt zuerst, wie viele eine Kategorie bekämen, und fragt; `enter` oder `y` tut es, und `z` setzt sie zurück, im Fenster oder nachdem es geschlossen ist. Es ist das, was `thaler cli recategorize` tut, und für die Regeln gedacht, die du geschrieben oder geändert hast, nachdem diese Transaktionen hereinkamen.

**Beim Kategorisieren eine Regel anlegen.** Drücke in der Kategorieauswahl `tab`, um in ein Feld *Regel* zu wechseln. Es beginnt mit dem Empfänger; kürze ihn auf den Teil, der zählt (`REWE Markt GmbH Filiale 12` → `REWE`). Während du tippst, sagt die Auswahl, wie viele andere Transaktionen ohne Kategorie sie erfassen würde. `enter` kategorisiert dann diese Transaktion, hängt die Regel an `config.toml` an und kategorisiert auch die passenden. `z` nimmt die Kategorien in einem Schritt zurück; die Regel bleibt in der Datei (drücke `C`, um sie zu entfernen). Geschrieben wird immer nur das Ende der Datei, deine Kommentare und die Reihenfolge deiner Regeln bleiben also unberührt. Regeln werden von oben nach unten geprüft, und die erste passende gewinnt; entscheidet eine frühere Regel diesen Empfänger schon anders, nennt die Auswahl diese Regel und lehnt ab, statt eine anzulegen, die nie greifen könnte.

In der Kategorieauswahl steht die Kategorie zuerst, die du zuletzt für denselben Empfänger verwendet hast (markiert mit „gleicher Empfänger“). Gleich danach (oder zuerst, wenn der Empfänger neu ist) kommt die Kategorie von Empfängern, die ihm ähneln (markiert mit „ähnlicher Empfänger“): Banken schreiben ein Geschäft auf viele Arten („REWE SAGT DANKE 4711“, „REWE Markt Berlin“), deshalb vergleicht Thaler die Wörter des Empfängers, ohne Zahlen, Rechtsformen (GmbH) und Buchungswörter (Kartenzahlung), und zählt ein Wort, das wenige deiner Empfänger haben (REWE), mehr als eines, das viele teilen (Deutsche, Berlin), damit „Deutsche Bahn“ nicht die Kategorie von „Deutsche Bank“ übernimmt. Es ist nur ein Vorschlag, nach vorne gestellt, damit `c` `enter` ihn nimmt, wird nie von selbst angewendet und fehlt, wenn nichts ähnlich genug aussieht. Dann kommen die Kategorien der passenden Art (Einnahmen für hereinkommendes Geld, Ausgaben für hinausgehendes), die meistbenutzten zuerst. Tippe, um zu filtern, oder tippe einen vollständigen neuen Namen wie `Expenses:Gifts`, um ihn anzulegen. Umbuchungen und aufgeteilte Transaktionen werden gezeigt, lassen sich dort aber nicht umkategorisieren.

**Backups machen.** Drücke `S`, um das Backup-Fenster zu öffnen. Es zeigt die Datenbank, wann das letzte Backup gemacht wurde („2026-10-22 14:00 · vor 3 Tagen“) und wie viele im Backup-Ordner liegen, der neben der Datenbank liegt (`backups/`). `enter` schreibt einen Schnappschuss unter den Dateinamen in der Zeile *Ziel*, die mit `thaler-<Datum>-<Uhrzeit>.db` in diesem Ordner beginnt. Du kannst stattdessen jeden anderen Pfad tippen (`~` ist dein Home-Ordner) oder nur einen Ordner, der den Namen mit Zeitstempel darin bekommt. Eine Datei, die schon existiert, wird nie überschrieben. Nach dem Schreiben öffnet Thaler den Schnappschuss und führt die Integritätsprüfung von SQLite darauf aus; ein Schnappschuss, der durchfällt, wird entfernt und gemeldet, ein angekündigtes Backup ist also eines, das sich öffnen lässt.

**Eine Erinnerung ans Backup.** Ist das neueste Backup im Backup-Ordner 7 Tage alt oder älter, oder gibt es keines und du hast Transaktionen, beginnt die untere Leiste mit „Letztes Backup vor 9 Tagen: S erstellt ein neues“ (oder „Noch kein Backup“), bis du eines machst. Setze `backup_reminder_days = 14` in `config.toml` für einen anderen Abstand oder `0`, um die Erinnerung auszuschalten. Es zählen nur Backups im Backup-Ordner, wie im Fenster; solche, die du woanders geschrieben hast, und die Kopien in `replaced/` und `pre-migration/` nicht. Geprüft wird beim Start von Thaler, nach einem Backup, nach dem Bearbeiten der Konfiguration und (höchstens einmal pro Minute) bei einem Tastendruck, ein Backup, das ein Skript bei offenem Thaler macht, beendet die Erinnerung also auch.

**Alte Backups aufräumen.** Backups stapeln sich, und nichts entfernt eines von selbst. Thaler behält die neuesten 10 in jedem von drei Ordnern: die Backups, die du machst (`backups/`), die Datenbanken, die Wiederherstellungen ersetzt haben (`backups/replaced/`), und die Kopien vor Upgrades (`backups/pre-migration/`). Liegen in einem Ordner mehr, sagt die untere Leiste „3 alte Backups können entfernt werden: ctrl+p“. `ctrl+p` listet genau, welche Dateien gehen würden, die ältesten, mit Datum und Größe, und `enter` entfernt sie; `esc` lässt sie. „Alt“ ist der Zeitpunkt der letzten Änderung einer Datei, einfache und verschlüsselte Backups zählen zusammen, und die neuesten bleiben immer. Aufgelistet werden nur Dateien, die wie ein Backup heißen (`thaler-*.db`, `thaler-*.db.age`), alles andere in diesen Ordnern und Backups, die du woanders geschrieben hast, wird also nie angefasst. Setze `keep_backups = 20` in `config.toml` für eine andere Anzahl oder `0`, um alles zu behalten und das Angebot abzuschalten. Aus einem Skript listet `thaler cli prune`, was gehen würde, und `thaler cli prune --yes` entfernt es. Entfernen ist endgültig; ein entferntes Backup liegt nicht im Papierkorb.

**Ein Backup verschlüsseln.** Standardmäßig ist ein Backup eine einfache SQLite-Datei, die jeder lesen kann, der sie in die Hände bekommt. Drücke `tab` bis zur Zeile *Passphrase* und tippe eine (sie erscheint als `•`), dann `tab` zu *Wiederholen* und tippe sie noch einmal, damit dich ein Tippfehler nicht aussperrt. Das Backup wird dann als [age](https://age-encryption.org)-Datei mit der Endung `.age` geschrieben, versiegelt mit einem Schlüssel, den scrypt aus der Passphrase ableitet (das dauert absichtlich ein, zwei Sekunden; das Fenster zeigt solange einen Spinner und was es gerade tut und ignoriert Tasten, bis es fertig ist, außer `ctrl+c`, das gleich danach beendet). Thaler entschlüsselt das Ergebnis einmal, bevor es sagt, dass es fertig ist, um sicherzugehen, dass die Passphrase, die es hat, es öffnet. Die unverschlüsselte Kopie gibt es nur einen Moment lang, in einem privaten Ordner neben dem Backup, und sie wird gelöscht. **Ein Backup, dessen Passphrase verloren ist, lässt sich auf keinem Weg wiederherstellen.** Fenster und Statuszeile sagen, ob ein Backup verschlüsselt ist, und die Zeile *Zuletzt* sagt es für das neueste.

**Eine Kopie vor jedem Upgrade.** Muss eine neue Version von Thaler die Struktur einer Datenbank ändern, die schon Daten enthält, schreibt sie zuerst eine geprüfte Kopie nach `backups/pre-migration/` neben der Datenbank, benannt `thaler-<Zeit>-before-<Migration>.db`, und sagt auf der Standardfehlerausgabe, wo sie liegt. Lässt sich die Kopie nicht machen, findet das Upgrade nicht statt, und nichts ändert sich. Eine neue Datenbank, eine, die schon aktuell ist, und eine, die eine neuere Version geschrieben hat (die abgelehnt wird), bekommen keine Kopie. Diese Kopien sind nicht verschlüsselt und werden getrennt von deinen eigenen Backups aufbewahrt, damit sie nie als dein „letztes Backup“ zählen; `ctrl+p` und `thaler cli prune` räumen sie auf (siehe oben).

**Wiederherstellen.** `thaler cli restore FILE` ersetzt die Datenbank durch ein Backup, einfach oder verschlüsselt (es fragt nach der Passphrase oder liest `--passphrase-file`). Das Backup wird zuerst in eine neue Datei gelesen und geprüft: Eines, das beschädigt ist, keine Thaler-Datenbank ist oder von einer neueren Version stammt, wird abgelehnt, ohne dass sich etwas ändert. Erst dann wird die vorhandene Datenbank verschoben, nie gelöscht, nach `backups/replaced/` daneben, und das Backup an ihre Stelle gesetzt. `thaler cli restore` auf der Datei in `backups/replaced/` macht eine Wiederherstellung rückgängig (der Befehl gibt sie aus). Es funktioniert auch, wenn die vorhandene Datenbank beschädigt ist oder fehlt. Ein Backup einer älteren Version wird beim nächsten Start von Thaler aktualisiert, nach einer Kopie davon. Schließe vorher jedes andere Thaler; die Wiederherstellung sucht nicht danach.

**Aus der Oberfläche wiederherstellen.** `ctrl+r` öffnet das Wiederherstellungsfenster. Es listet die Backups im Backup-Ordner, das neueste zuerst, dann die Datenbanken, die frühere Wiederherstellungen ersetzt haben (markiert mit „bei Wiederherstellung ersetzt“), eine Wiederherstellung lässt sich also an derselben Stelle zurücknehmen. Wähle eines mit `↑`/`↓`; für ein verschlüsseltes Backup `tab` zu *Passphrase* und tippe sie. `enter` fragt noch einmal und nennt die Datei und wo deine aktuelle Datenbank aufbewahrt wird, und ein zweites `enter` (oder `y`) stellt wieder her. Bis dahin passiert nichts, und ein Backup, das beschädigt ist, die falsche Passphrase hat oder keine Thaler-Datenbank ist, wird abgelehnt, die Datenbank bleibt unberührt und das Fenster offen. Nach einer Wiederherstellung zeigt der Bildschirm die wiederhergestellten Daten, und das Rückgängigmachen beginnt von vorn (es reicht nicht darüber hinaus). Ein Backup, das nicht im Ordner liegt: `thaler cli restore FILE`.

Um ein verschlüsseltes Backup wieder zu öffnen, fragt `thaler cli decrypt FILE.age [DEST]` nach der Passphrase und schreibt eine einfache Datenbank (standardmäßig der Dateiname ohne `.age`; eine vorhandene Datei wird nie überschrieben, und eine falsche Passphrase hinterlässt nichts). Benutze das Ergebnis mit `thaler --db DEST`. Weil es eine gewöhnliche age-Datei ist, öffnet sie auch das Werkzeug `age` (`age -d`).

In Terminals mit weniger als 76 Spalten wird der Detailbereich ausgeblendet, und unter 14 Zeilen wird nur das fokussierte Fenster gezeigt.

## Mehrere Währungen

- Jedes Konto hat eine Währung (Vermögen/Verbindlichkeiten) oder nimmt jede an (Einnahmen/Ausgaben/Eigenkapital). Beträge werden beim Speichern nie umgerechnet.
- Die **Basiswährung** betrifft nur die Berichte: `thaler cli currency` zeigt sie, `thaler cli currency set USD` ändert sie.
- **Wechselkurse** trägst du selbst ein: `thaler cli rate set USD EUR 0.92` heißt 1 USD = 0.92 EUR. Eine Richtung genügt; die umgekehrte wird abgeleitet, und USD → MXN geht über jede Währung, die Kurse zu beiden hat (etwa EUR). Berichte verwenden den neuesten Kurs am Berichtsdatum oder davor.
- **Budgets zählen jeden Tag zu seinem eigenen Kurs.** Ausgaben und Einnahmen in einer anderen Währung werden zum neuesten Kurs am Tag ihrer Buchung oder davor in die Basiswährung umgerechnet, ein später eingetragener Kurs verschiebt also keinen schon gezählten Monat; ein Tag vor dem ersten Kurs seiner Währung nimmt den Kurs am Monatsende. Ein Ziel ist in der Basiswährung, die Budgetansicht und `thaler cli budget` vergleichen es also mit den Ausgaben in jeder Währung, und eine Währung ganz ohne Kurs wird genannt und weggelassen.
- `thaler cli balance` zeigt jedes Konto in seiner eigenen Währung und dazu ein Nettovermögen in der Basiswährung. Währungen ohne brauchbaren Kurs werden in einer Warnung genannt und aus der Summe weggelassen, statt geraten zu werden.
- Geld zwischen Währungen bewegen: `thaler cli transfer --from Assets:Sparkasse --to Assets:Cash-USD --amount 100 --to-amount 108.50`. Es wird über `Equity:Conversions` gebucht, damit jede Währung für sich aufgeht, und der tatsächliche Kurs wird ausgegeben.

```sh
./thaler cli account add Assets:Cash-USD --currency USD
./thaler cli account add Assets:Cash-MXN --currency MXN
./thaler cli rate set USD EUR 0.92
./thaler cli rate set MXN EUR 0.05
./thaler cli currency set USD
./thaler cli balance
```

## Befehle

Ohne Argumente öffnet `thaler` die Terminaloberfläche (siehe oben). Alles andere liegt unter `thaler cli`; `thaler cli --help` zeigt die Liste. Die Oberfläche braucht ein Terminal, Skripte und Cron-Jobs verwenden also immer `thaler cli`, das Englisch spricht.

| Befehl | Zweck |
| --- | --- |
| `thaler cli account add NAME -c EUR` / `thaler cli account list` | der Kontenplan; das erste Segment ist der Typ (`Assets:`, `Liabilities:`, `Income:`, `Expenses:`, `Equity:`) |
| `thaler cli account rename OLD NEW` | einem Vermögens- oder Verbindlichkeitskonto einen neuen Namen geben; seine Transaktionen, Zeitpläne und sein Minimum bleiben bei ihm |
| `thaler cli account close ACCOUNT` / `thaler cli account reopen ACCOUNT` | ein leeres Konto beiseitelegen und seinen Verlauf behalten, oder es zurückholen (siehe oben) |
| `thaler cli account balance ACCOUNT AMOUNT [--as-of DATE]` | das Konto über einen Anfangssaldo auf das bringen, was deine Bank zeigt |
| `thaler cli add -a ACCOUNT --amount=-12.50 -t CATEGORY -p PAYEE -d DATE` | eine Einnahme oder Ausgabe |
| `thaler cli split ID --line CATEGORY[=AMOUNT]... [--amount N] [--date D] [--payee P] [--memo T]` | eine Transaktion auf Kategorien aufteilen oder ändern, wie sie aufgeteilt ist: Die angegebenen Zeilen ersetzen alle, eine darf ihren Anteil weglassen und nimmt den Rest, und sie müssen den Betrag ergeben, sonst ändert sich nichts; eine einzige Zeile macht sie wieder zu einer gewöhnlichen Transaktion |
| `thaler cli transfer --from A --to B --amount N [--to-amount M]` | zwischen deinen eigenen Konten, auch zwischen Währungen |
| `thaler cli transfer edit ID [--from A] [--to B] [--amount N] [--to-amount M] [--date D] [--in-date D] [--memo T]` / `transfer delete ID [--yes]` | beide Hälften einer Umbuchung zusammen ändern oder löschen, mit der Nummer einer der beiden |
| `thaler cli transfer link A B` / `transfer unlink ID` | zwei gespeicherte Transaktionen zu den Hälften einer Umbuchung machen oder wieder zu zwei gewöhnlichen (ohne Kategorie) |
| `thaler cli import FILE -a ACCOUNT [--profile P] [--dry-run]` | einen Bankexport importieren: CSV, OFX oder QIF; das Profil wird aus der Datei ermittelt (`auto`, der Standard), es sei denn, `--profile` nennt eines (`sparkasse`, `ofx`, `qif` oder ein eigenes) |
| `thaler cli list [-a ACCOUNT] [--from D] [--to D] [-n 30]` | Transaktionen, die neuesten zuletzt |
| `thaler cli export [DEST] [-a ACCOUNT] [--from D] [--to D]` | die Transaktionen als CSV für eine Tabellenkalkulation, die älteste zuerst, eine Zeile pro Buchungszeile (ID, Datum, Empfänger, Notiz, Konto, Betrag, Währung; englische Spaltennamen, Beträge als Dezimalzahlen mit Punkt); auf die Standardausgabe oder in eine neue, nur für dich lesbare Datei, die nie überschrieben wird |
| `thaler cli recategorize [--dry-run]` | die Regeln aus config.toml auf Transaktionen anwenden, die noch keine Kategorie haben |
| `thaler cli category set ID CATEGORY` | eine Transaktion in eine andere Kategorie verschieben (die angelegt wird, wenn sie neu ist) |
| `thaler cli balance [--as-of D] [--all]` | Salden und Nettovermögen |
| `thaler cli budget [-m YYYY-MM]` / `thaler cli budget set CATEGORY AMOUNT [-m M]` / `thaler cli budget clear CATEGORY [-m M]` | die Ausgaben eines Monats gegen seine Ziele (ausgegeben, Ziel, übertragen, übrig), eine zweite Tabelle mit den zusammengerechneten Kategoriegruppen (siehe Kategoriegruppen) und, wenn Einkommen geplant ist, die Einnahmen gegen ihren Plan und was nicht zugeteilt ist; das Ziel einer Kategorie setzen oder entfernen (das einer Einnahmenkategorie ist das geplante Einkommen); der Monat ist standardmäßig dieser, Beträge sind in der Basiswährung |
| `thaler cli report spending [--months]` / `cashflow` / `payees [--limit N]` / `networth`, jeweils mit `[--from YYYY-MM] [--to YYYY-MM]` | die Berichte der Berichtsansicht als Tabellen, für die 12 Monate bis zu diesem oder die angegebenen Monate (höchstens 120): Ausgaben pro Kategorie mit Summe und Monatsdurchschnitt (`--months`: eine Spalte pro Monat), was hereinkam gegen was hinausging mit dem gesparten Anteil, die Empfänger, die am meisten bekamen, mit ihrem Anteil (20 aufgeführt, der Rest in einer Zeile; `--limit 0` führt alle auf), und das Nettovermögen am Ende jedes Monats mit der Änderung; Beträge sind in der Basiswährung, jeder zum Kurs seines Tages, und eine Währung ohne Kurs wird in einer Warnung genannt |
| `thaler cli forecast [--until D]` | der Saldo jedes Kontos heute und nach jedem Tag, an dem ein Zeitplan ihn bewegt |
| `thaler cli account minimum [ACCOUNT [AMOUNT] \| --amount N \| --clear]` | der niedrigste Stand, auf den ein Vermögenskonto fallen soll; `forecast` warnt vor dem Tag, an dem es so weit wäre |
| `thaler cli schedule` / `add NAME --unit U -a A --amount N [--to ACCOUNT] [--tolerance P] [--end D]` / `edit ID` / `delete ID` / `pause ID` / `resume ID` / `due [--until D]` / `confirm ID DATE [--amount N] [--to-amount N]` / `skip ID DATE` | wiederkehrende Transaktionen: anlegen, die fälligen Termine auflisten und jeden bestätigen (auf Wunsch mit einem anderen Betrag) oder überspringen; ohne Bestätigung wird nichts gebucht |
| `thaler cli currency [set CODE]`, `thaler cli rate set/list` | Basiswährung und Wechselkurse |
| `thaler cli backup [DEST] [--encrypt \| --passphrase-file F]` | konsistenter Schnappschuss über `VACUUM INTO`, nach dem Schreiben geprüft; **unverschlüsselt**, außer mit `--encrypt` (fragt zweimal nach einer Passphrase) oder `--passphrase-file` (die erste Zeile einer Datei, für Skripte), die eine age-Datei mit der Endung `.age` schreiben; auch `S` in der Oberfläche |
| `thaler cli decrypt SRC [DEST] [--passphrase-file F]` | ein verschlüsseltes Backup als einfache Datenbankdatei öffnen und prüfen |
| `thaler cli prune [--keep N] [--yes]` | die Backups über die neuesten N in jedem Backup-Ordner hinaus auflisten (standardmäßig 10 oder `keep_backups`); mit `--yes` entfernen |
| `thaler cli restore SRC [--passphrase-file F]` | die Datenbank durch ein Backup ersetzen (einfach oder verschlüsselt) und die ersetzte in `backups/replaced/` behalten; auch `ctrl+r` in der Oberfläche |
| `thaler cli check` | prüft, dass jede Transaktion pro Währung aufgeht und die Datenbank intakt ist |

Schreibe negative Beträge als `--amount=-12.50`. Beträge nehmen `12.50`, `12,50` und `1.234,56` an; eine mehrdeutige Eingabe wie `1,234` wird abgelehnt, statt geraten zu werden.

**Für Skripte: `--json`.** Jede Auflistung (`account list`, `account minimum`, `list`, `balance`, `budget`, `rate list`, `schedule list`, `schedule due`, `forecast`, `prune` und die vier `report`s) nimmt `--json` an, das ein einziges JSON-Dokument statt der Tabelle ausgibt und sonst nichts (was eine Tabelle in einer Warnung sagt, etwa eine Währung ohne Wechselkurs, steht in den Daten als Liste `missing`; `prune --json` listet nur und lehnt `--yes` ab). Das Dokument ist die Antwort des Dienstes, überall gleich geschrieben: Objekte haben Schlüssel in `snake_case` in fester Reihenfolge (`spent_total`, `schedule_id`), Listen sind leer `[]` und nie `null`, ein Betrag ist `{"amount": "-12.50", "currency": "EUR"}` mit dem Betrag als Text mit Punkt (nie als Zahl, damit keine Stelle verloren geht), Tage sind `YYYY-MM-DD`, Monate `YYYY-MM`, Zeitpunkte RFC 3339 in UTC, und ein Wechselkurs ist seine exakte Dezimalzahl als Text. `thaler cli export` schreibt Transaktionen als CSV.
